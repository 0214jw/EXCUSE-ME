# EXCUSE ME!

일상 속 황당하고 창의적인 핑계를 예술 작품처럼 등록하고 감상하는 참여형 디지털 박물관.

**텍스트·원본 사진 작품 기증, 조회·수정·삭제, 좋아요·명예의 전당과 랜덤 감상을 구현했습니다.** 기존 설치미술 히어로·블랙 인트로·AI 큐레이터·AI 회화 저장 구조는 유지합니다. 유료 이미지 생성은 기본 OFF이며 이번 사진 기능에서는 사진을 OpenAI에 보내지 않습니다. 원본 사진의 제한·저장·검증 상태는 **15절**, 기존 AI 이미지 비용·설정은 14절, 이력은 [PROGRESS.md](docs/PROGRESS.md)를 참고합니다. 사진 AI 변환·Vision·전체 리디자인은 구현하지 않았으며 실제 브라우저 검증은 자동 검사와 별도로 남아 있습니다.

## 1. 폴더 구성

```text
frontend/   React + Vite + Tailwind CSS 화면
backend/    FastAPI 서버, 패키지 목록, 로컬 .venv
database/   서버 최초 실행 시 생성되는 SQLite DB (Git 제외)
docs/       MVP, PRD, SPEC, PLAN 기획 문서
```

`node_modules`, `.venv`, `dist`, 로그, 실제 `.env`와 SQLite DB 파일은 기존 `.gitignore` 규칙에 따라 Git에서 제외됩니다. 비밀값이 없는 `.env.example`은 공유할 수 있습니다.

## 4. 실행하기: 터미널 두 개 사용

### 터미널 1 — 백엔드

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\backend"
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

서버가 실행되는 동안 이 터미널은 켜 둡니다. 브라우저에서 <http://127.0.0.1:8000/api/health>를 열면 `{"status":"ok"}`가 표시됩니다. 자동 API 문서는 <http://127.0.0.1:8000/docs>입니다.

### 터미널 2 — 프론트엔드

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\frontend"
npm.cmd run dev
```

브라우저에서 **<http://localhost:5173>**을 열면 랜딩페이지가 표시됩니다. **전시 관람하기**로 <http://localhost:5173/gallery>에 이동합니다. 서버 연결 테스트는 하단 **서버 연결 확인** 링크 또는 **<http://localhost:5173/health>**에서 실행합니다.

두 서버는 각각 해당 터미널에서 `Ctrl+C`로 종료합니다. 다시 실행하려면 같은 실행 명령을 입력합니다. 현재 명령은 코드 변경 후 자동 재시작을 설정하지 않으므로, 백엔드 코드를 고쳤다면 종료 후 다시 실행합니다.

프론트엔드 포트는 `5173`으로 고정했고, 사용 중이면 다른 포트로 자동 이동하지 않고 오류를 표시합니다. 포트가 이미 사용 중일 때는 기존에 실행한 서버인지 확인하고 그 터미널에서 종료한 뒤 다시 실행합니다.

## 5. 서버 주소 설정

기본 서버 주소는 `http://127.0.0.1:8000`이며 `.env` 없이 실행할 수 있습니다. 변경이 필요할 때만 다음 명령으로 예시를 복사합니다.

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\frontend"
Copy-Item .env.example .env
```

생성한 `.env`의 `VITE_API_BASE_URL`을 변경하고 프론트엔드를 재시작합니다. 이미 `.env`가 있다면 복사 명령으로 덮어쓰지 말고 기존 파일을 편집합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀번호나 API 키를 넣지 않습니다.

FastAPI는 `http://localhost:5173`과 `http://127.0.0.1:5173`에서 오는 GET·POST와 JSON Content-Type을 허용합니다. 이 설정을 CORS라고 하며, 다른 주소의 화면이 서버 응답을 읽을 수 있는지 브라우저에 알려줍니다. 프론트엔드 포트를 바꾸면 `backend/main.py`의 허용 주소도 함께 바꿔야 합니다.

## 6. 연결 확인 화면에서 직접 확인할 동작

1. 두 서버를 켜고 <http://localhost:5173/health>를 엽니다. 연결 확인 화면의 제목과 버튼이 보이는지 확인합니다.
2. **서버 연결 확인**을 누르면 **연결 성공**과 `{"status":"ok"}`가 표시되어야 합니다.
3. 백엔드 터미널에서 `Ctrl+C`를 누릅니다. 프론트엔드 터미널은 유지합니다.
4. 같은 버튼을 다시 누르면 **연결 실패**와 백엔드 실행 여부를 확인하라는 안내가 표시되어야 합니다. 이전 성공 응답은 사라져야 합니다.
5. 백엔드를 같은 명령으로 다시 실행하고 버튼을 누르면 다시 성공해야 합니다.
6. 두 터미널에서 각각 `Ctrl+C`로 종료한 뒤 다시 실행해 봅니다.

연결 요청 중에는 버튼이 비활성화되고 **연결 확인 중…**을 표시합니다. 5초 안에 응답을 받지 못하면 시간 초과 안내를 표시하도록 구현했습니다. 연결 상태는 마지막 버튼 클릭 시점의 결과이며 자동 감시 기능은 없습니다.


## 9. DB·방문객 ID·API

서버를 처음 실행하면 프로젝트의 `database/excuse_me.sqlite3`에 작품 테이블을 생성합니다. 제목·내용·카테고리·작가명·방문객 ID·작품 ID·등록일·수정일과 재시도 구분용 요청 ID를 저장합니다. DB는 파일에 남아 서버를 껐다 켜도 유지됩니다. 서버의 작업 폴더를 바꿔도 기본 DB 경로는 같습니다. 등록·수정일은 UTC로 저장하고 화면은 한국 시간으로 표시합니다. 수정 기능은 아직 없습니다.

실제 DB와 저널 파일은 `.gitignore`로 제외됩니다. DB 구조는 `backend/database.py`에서 재현합니다. 테스트나 별도 저장소가 필요하면 서버 실행 전에 `EXCUSE_ME_DB_PATH` 환경변수에 원하는 파일 경로를 지정할 수 있습니다. 일반 실행에서는 지정할 필요가 없습니다.

최초 방문 시 UUID v4를 브라우저 localStorage의 `excuse-me.visitor-id`에 저장합니다. 새로고침·재방문 시 유지되지만 다른 브라우저·기기·origin은 별개입니다. 예를 들어 `localhost:5173`과 `127.0.0.1:5173`은 저장소를 공유하지 않습니다. 저장소를 사용할 수 없으면 조회는 가능하지만 기증은 입력을 유지하며 오류를 안내합니다.

**이 방문객 ID는 실제 인증 수단이 아닙니다.** 사용자가 복사·변경할 수 있으므로 보안이 필요한 권한을 보장하지 않습니다. 작가명도 인증 정보가 아닙니다. 저장소를 지우면 이전 ID를 잃을 수 있으며 ID 복구는 제공하지 않습니다. API의 공개 조회 응답에는 방문객 ID와 요청 ID를 노출하지 않습니다.

| API | 동작 |
| --- | --- |
| `GET /api/health` | 기존 `{"status":"ok"}` 응답 |
| `POST /api/artworks` | JSON `title`, `content`, `category`, 선택 `author`, UUID v4 `visitor_id`, 선택 UUID v4 `request_id`. 선택 `refined_description`은 `description_confirmed: true`일 때만 저장. 신규 저장은 201과 작품·Location 반환 |
| `POST /api/curator` | 원문·현재 제목(빈 값 가능)·카테고리·방문객/요청 UUID를 보내 제목 3개와 작품 설명을 함께 추천. 작품은 저장하지 않음 |
| `GET /api/artworks` | 작품 배열, 최신 등록순, 같은 등록 시각이면 ID 내림차순. 빈 DB는 `[]` |
| `GET /api/artworks/{id}` | 작품 단건, 없는 작품 404, 잘못된 ID 422 |

입력 오류는 422와 `errors`의 항목별 안내, DB 오류는 503입니다. 내부 DB 경로나 원본 입력값을 오류 응답에 그대로 포함하지 않습니다. 수정·삭제 API는 없습니다.

기증 중에는 입력과 제출 버튼을 잠그고 중복 실행을 막습니다. 같은 화면에서 같은 입력을 다시 기증하면 동일한 `request_id`를 재사용하고 서버는 기존 작품을 200으로 반환합니다. 같은 방문객·요청 번호에 다른 내용을 보내면 409입니다. API를 직접 호출하면서 `request_id`를 생략하면 서버가 새 번호를 만들므로 재시도 중복 방지를 원하면 같은 번호를 전달해야 합니다.

응답이 없거나 서버 오류가 나면 저장됐을 가능성도 함께 안내하고 자동 재시도하지 않습니다. 화면에 입력은 유지되며 직접 재시도할 수 있습니다. 새로고침·화면 이탈 뒤에는 입력과 재시도 키를 보존하지 않으므로 불확실한 결과는 전시관에서 확인하세요.

## 11. 상세 감상실 확장 준비

백엔드를 다시 실행하면 기존 테이블에 `refined_description`, `image_url`, `image_mode`, `image_style` 선택 컬럼만 자동 추가됩니다. 기존 작품과 원문 `content`, 작품 번호·방문객 정보·등록일은 보존됩니다. 기존 작품의 새 필드는 NULL이며 테이블을 재생성하지 않습니다. 코드 검사에서는 실제 DB의 임시 복제본으로도 보존을 확인했습니다.

상세 화면 왼쪽은 액자와 이미지 자리, 오른쪽은 작품명·작가명·작품 설명·기증 날짜·카테고리·기증 버튼 순서입니다. 이미지가 없으면 **작품 이미지는 준비 중입니다.**, 별도 설명이 없으면 원문을 포함한 **임시 설명**을 표시합니다. 임시 설명을 DB에 저장하거나 원문을 덮어쓰지 않습니다. 작은 화면은 이미지 위·정보 아래로 배치합니다.

AI 큐레이터의 사용자 확인된 설명은 `refined_description`에 저장합니다. 서버가 생성한 이미지의 임시 확인 토큰으로 기증하면 `image_url`·`image_mode=generated`·`image_style`을 연결합니다. 클라이언트가 임의의 이미지 URL/경로를 등록할 수 없습니다. `photo`는 향후 확장용이며 현재 입력으로 받지 않습니다. 화면의 `ArtworkExhibition.jsx`·`artworkPresentation.js`는 조회된 이미지와 설명을 표시합니다.

설명이 없는 기존 작품의 임시 설명은 고정 문장과 원문을 조합한 표시이며 GPT 결과가 아닙니다. 별도 설명이 있으면 이를 표시하고 `원문 핑계 확인하기`로 원문도 볼 수 있습니다. 생성 이미지 서빙은 기증된 작품에만 제공하며 사진 업로드·화풍 변환은 구현하지 않았습니다. 새 이미지의 실제 브라우저 배치·실패·모바일은 직접 확인이 필요합니다.

## 13. AI 큐레이터 사용과 안전한 키 설정

현재 원문을 입력하고 카테고리를 선택한 뒤 작품명 근처의 **AI 큐레이터에게 작품 추천받기**를 누릅니다. 작품명을 비워도 추천받을 수 있습니다. 제목 3개 중 하나를 고르거나 직접 수정하고, 별도 설명 영역에서 해설을 읽고 수정하세요. **이 설명을 확인했으며 작품 설명으로 함께 저장합니다**를 선택한 설명만 최종 기증 시 저장합니다. 원문과 설명은 별도 컬럼이며 후보 목록은 DB에 저장하지 않습니다. 확인하지 않으면 기존 텍스트 작품만 기증합니다.

제목 변경만으로 재생성하지 않습니다. **다시 생성하기**를 눌렀을 때만 새 요청을 보냅니다. 원문/카테고리 수정 시 오래된 결과 안내를 표시하고, 원문·제목·카테고리·설명 수정 시 확인 체크를 해제합니다. 실패해도 작품 입력과 편집한 내용은 유지되며 AI 없이 기증할 수 있습니다.

기본 모델은 **`gpt-5.6-terra`**입니다. 공식 문서의 mini급 지능·비용 균형과 구조화 출력 지원을 기준으로 선택했습니다. FastAPI가 `POST https://api.openai.com/v1/responses`를 한 번 호출하며 `reasoning.effort: none`, strict JSON Schema, `max_output_tokens: 1000`, `store: false`를 사용합니다. 서버가 제목 개수/길이/다양성, 한국어 설명 2~4문장을 다시 검사합니다. 문체·새 사실을 만들지 않는 정도는 사용자가 실제 결과로 확인해야 합니다. [모델](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

API 키는 사용자가 [OpenAI API 키 설정](https://platform.openai.com/settings/organization/api-keys)에서 적절한 프로젝트의 키를 직접 발급합니다. 프로젝트의 사용량·지출 설정과 필요한 권한을 확인하고 키를 채팅·코드·브라우저·Git에 넣지 마세요. [공식 키 관리 안내](https://developers.openai.com/api/docs/guides/production-best-practices).

`backend/.env.example`에는 변수명과 빈 키만 제공합니다. 이 파일을 복사하는 것만으로는 자동 로드되지 않습니다. **백엔드 터미널에서만**, 아래처럼 숨김 입력으로 프로세스 환경변수를 설정한 후 서버를 실행하세요. 실행 중인 이전 백엔드는 먼저 해당 터미널에서 `Ctrl+C`로 종료합니다. `.env`나 저장소 설정을 덮어쓸 필요는 없습니다.

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\backend"
$curatorSecret = Read-Host "OpenAI API key" -AsSecureString
$curatorPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($curatorSecret)
try {
  $env:OPENAI_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($curatorPointer)
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($curatorPointer)
}
$env:OPENAI_CURATOR_MODEL = 'gpt-5.6-terra'
$env:OPENAI_CURATOR_TIMEOUT_SECONDS = '20'
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

`VITE_` 변수는 브라우저에 공개되므로 OpenAI 키를 넣지 않습니다. 키 없이 서버를 실행해도 일반 등록·조회는 정상이며 AI 버튼에는 설정 안내가 표시됩니다. 요청 본문·키·제공사 원본 오류를 로그에 남기지 않습니다. 키가 설정된 상태에서 버튼을 누르면 실제 유료 API 요청이 발생할 수 있습니다.

기본 네트워크 제한 시간은 20초(설정은 5~25초로 제한), 브라우저는 30초입니다. 자동 재시도·리다이렉트 재요청은 없습니다. 단일 프로세스 메모리 기준 10분간 방문객 5회·연결 IP 10회·전체 30회, 동시 2건으로 제한합니다. 동일 방문객/IP의 진행 중 요청과 요청 UUID 재전송은 차단합니다. 실패 시도도 횟수에 포함하며 재시작 시 한도가 초기화됩니다. 여러 worker/서버 사이의 공유 제한이나 정식 인증은 이번 범위가 아닙니다.

브라우저에서 확인할 순서:

1. 키 없이 AI 추천 오류 안내를 확인하고 직접 제목을 입력해 텍스트 기증이 되는지 확인합니다.
2. 키를 안전하게 설정하고 백엔드를 다시 실행한 뒤 원문·카테고리를 입력하고 추천 버튼을 한 번 누릅니다. 제목 3개와 해설이 함께 나와야 합니다.
3. 후보 제목을 고른 뒤 직접 고칩니다. 설명이 자동으로 다시 생성되지 않아야 합니다.
4. 설명을 수정하고 확인 체크 후 기증합니다. 상세 화면의 최종 제목/설명과 원문 펼치기에서 원문 보존을 확인합니다.
5. 원문을 수정해 오래된 추천 안내·확인 해제를 확인합니다. 다시 생성 중 빠른 클릭을 반복해도 중복 요청이 생기지 않아야 합니다.
6. 설명 확인을 선택하지 않거나 AI 요청이 실패해도 기존 텍스트 기증이 가능해야 합니다. 사진·미완료 AI 이미지의 기증 차단도 유지되어야 합니다.

최초 구현 당시 에이전트 작업 환경에는 키가 없어 실제 OpenAI 생성 API를 호출하지 않았습니다. 이후 사용자가 **실제 API의 제목 3개 추천·미술관 스타일 설명 표시·결과 UI**를 브라우저에서 확인했습니다. 이번 저장 작업에서는 추가 실제 호출을 하지 않고 모의 전송 테스트만 재실행했습니다.

제목/설명 수정·확인 후 기증, 상세 재조회·새로고침/재시작 후 최종 설명 유지·원문 보존은 **코드 점검과 임시 DB 자동 검사 통과, 사용자 브라우저 미검증**입니다. 실제 모델의 다양한 원문에 대한 품질/사실 충실도, 지연·비용·실제 오류, 모바일·전체 브라우저 회귀도 미검증입니다. 다음으로 위 3~6번 저장·재조회 흐름을 직접 확인하면 됩니다. 코드는 연결되어 있으며 프로덕션에 가짜 추천 모드는 없습니다.

## 14. AI 회화 생성: 비용 확인 후 별도 유료 테스트

이번 개발·자동 검사에서는 실제 이미지 생성 API를 **한 번도 호출하지 않았습니다**. 운영 앱에 모의 이미지 모드는 없으며, 합성 PNG 모의 전송은 `backend/tests/painting_fixture.py` 등 테스트 전용입니다. 기존 키와 큐레이터 모델 설정도 변경하지 않았습니다. 현재 에이전트 터미널에는 키가 없어 프로젝트의 이미지 모델 접근 권한은 미검증입니다. 모델 목록에 보이는 경우에도 생성 권한·조직 인증·결제 상태까지 입증하지는 않습니다.

### 공유 키의 비용 보호

- `OPENAI_IMAGE_ENABLED=1`일 때만 서버에서 유료 요청을 허용합니다. 기본 OFF이며 키가 없어도 텍스트 기증·조회는 작동합니다. `.env.example`은 자동 로드되지 않습니다.
- 서버가 모델·크기·품질·장수·PNG를 고정합니다. 브라우저 요청으로 옵션을 높이지 못하며 앱은 자동 재시도하지 않습니다. 네트워크 제한 시간 120초, 브라우저 대기 150초, 리다이렉트 재요청 없음.
- SQLite에 호출 전에 예약합니다. **기본 24시간 3회, 누적 10회, 누적 예약액 100센트**, 방문객 또는 연결 IP당 5분 간격, 전체 동시 1건입니다. 1회 10센트를 예약하고 실패/시간 초과에도 돌려주지 않습니다. 프로세스를 재시작해도 기록을 유지합니다. 복수 worker도 같은 DB를 써야 합니다.
- 10센트는 예상 비용을 여유 있게 잡은 앱 예약 단위입니다. **OpenAI의 확정 청구액이나 계정 전체의 강제 과금 상한이 아닙니다.** 공유 키의 다른 앱·이전 요청 비용은 별개입니다. 선생님과 사용량·지출 알림/한도·프로젝트 권한을 확인하세요. 자동 설정 상향·원장 초기화는 하지 않습니다.
- 방문객 ID는 실제 인증 수단이 아닙니다. 전역 한도가 ID 변경에도 적용되지만, 이 데모를 공개 유료 서비스로 배포하기 위한 정식 인증·운영 정책을 대체하지 않습니다.

**별도 유료 테스트를 하기로 결정한 뒤**, 기존 키가 설정된 백엔드 터미널에서 첫 테스트를 1회로 제한하는 예시입니다. 지금 이 문서 작성 중에는 실행하지 않았습니다.

```powershell
# 기존 서버를 Ctrl+C로 종료한 뒤 backend 폴더에서 실행합니다.
# OPENAI_API_KEY와 OPENAI_CURATOR_MODEL은 기존 설정을 그대로 사용합니다.
$env:OPENAI_IMAGE_ENABLED = '1'
$env:OPENAI_IMAGE_DAILY_LIMIT = '1'
$env:OPENAI_IMAGE_TOTAL_LIMIT = '1'
$env:OPENAI_IMAGE_BUDGET_CENTS = '10'
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

기존 생성 시도 기록이 있으면 위 누적 1회 설정에서 거절될 수 있습니다. 원장을 삭제하지 말고 사용량을 확인한 뒤 승인한 한도만 조정합니다. 테스트 후에는 `OPENAI_IMAGE_ENABLED=0`으로 되돌리고 서버를 재시작하면 추가 이미지 호출이 차단됩니다. 키는 계속 백엔드 환경변수만 사용하며 `VITE_` 변수나 프론트엔드 코드에 넣지 않습니다.

### 파일·DB·공개 전환

`uploads/paintings/`에 서버가 만든 무작위 식별자의 PNG를 보관합니다. 전체 폴더는 Git에서 제외되며 정적 공개 폴더로 마운트하지 않습니다. PNG 크기/구조/체크섬을 검사하고 임시 파일 쓰기·flush·fsync·원자적 이름 변경 후 비공개 준비 상태를 기록합니다. 새 `image_generations` 테이블만 추가하며 기존 `artworks`와 원문을 삭제/재생성하지 않습니다.

생성 응답은 브라우저 메모리의 미리보기와 무작위 확인 토큰을 반환합니다. DB에는 토큰의 해시를 저장하고 URL/로그/localStorage에 넣지 않습니다. 미리보기의 기증 가능 시간은 24시간입니다. 화면 이탈은 공개 기증이 아니며 전시관에 표시되지 않습니다. 제목·원문·카테고리·확인된 설명·화풍을 바꾸면 새 이미지 확인이 필요합니다. 달라진 이미지와 작품 정보는 서버에서도 거절합니다.

사용자가 이미지를 확인하고 기증하면 `POST /api/artworks`가 토큰·방문객·작품 내용·만료·파일 해시를 검사하고 단일 DB 트랜잭션으로 작품/이미지 연결을 확정합니다. 파일을 또 옮기지 않으므로 DB 저장 실패는 비공개 미리보기 상태로 되돌아갑니다. 생성 파일 저장·준비 상태 저장 실패는 파일을 정리하고 공개 작품을 만들지 않습니다. 기증 성공 후에만 `GET /api/artworks/{id}/image`로 공개합니다. 상세·갤러리 이미지는 원래 비율을 유지하며 API 서버 주소로 읽습니다.

만료된 비기증 결과는 공개되지 않으며, 파일 정리는 아래 **선택적인 로컬 유지보수**로 실행할 수 있습니다. 실행 중인 생성의 만료 전 파일·기증된 이미지·작품·비용 원장은 지우지 않습니다. 프로세스 강제 종료로 남은 만료 PNG/tmp도 정리합니다. DB와 이미지 폴더는 함께 백업해야 합니다.

```powershell
# backend 폴더, 서버와 동일한 DB/이미지 경로 환경에서 실행
.\.venv\Scripts\python.exe -c "import database, paintings; database.initialize(); print(paintings.cleanup_previews())"
```

### 브라우저 확인

1. 이미지 호출 OFF 상태에서 `/submit`의 생성 버튼을 눌러 설정 안내와 입력 유지를 확인합니다. 텍스트 기증은 유지되며 원본 사진 기증은 15절을 따릅니다.
2. 별도 유료 테스트 설정 후 원문·작품명·카테고리를 작성합니다. 큐레이터를 사용했다면 제목/설명을 수정하고 설명 확인란을 선택합니다. 큐레이터 없이도 원문만으로 가능합니다.
3. **AI로 작품 만들기 → 화풍 선택 → 작품 이미지 생성하기**를 한 번 누릅니다. 제작 상태·중복 클릭 차단·미리보기·예상 비용을 확인합니다. 다시 생성하면 추가 비용이 들 수 있습니다.
4. 이때 `/gallery`에 작품이 아직 없는지 확인합니다. **이미지 확인란 → AI 회화 작품 기증하기** 후 상세 왼쪽 액자·오른쪽 최종 정보·원문 펼치기를 확인합니다.
5. 상세 새로고침·갤러리 카드/카테고리·백엔드 재시작 후 이미지를 확인합니다. 기존 텍스트 작품은 placeholder와 원문으로 정상 표시되어야 합니다.
6. 생성 후 제목/원문/설명/화풍 변경, 미확인·만료·오류 안내, 모바일 이미지 비율도 확인합니다. 추가 유료 재생성 없이 가능한 상태만 먼저 검사하세요.

자동 검사는 위 흐름을 합성 PNG·임시 DB/폴더·모의 전송으로 검사합니다. 실제 유료 API, 공유 키 권한/결제/조직 인증, 실제 생성 품질·문자 배제·지연/비용, 새 화면 브라우저 클릭·모바일은 미검증입니다.

## 15. 원본 사진 작품 기증 (Phase 6)

이번 단계는 원본 사진 업로드이며 사진을 OpenAI로 보내거나 변환하지 않습니다. 기존 AI 큐레이터는 제목·핑계·카테고리 같은 **텍스트만** 사용합니다. 기존 AI 이미지 생성 기능과 별개이며 `OPENAI_IMAGE_ENABLED=0`을 유지합니다.

### 실행과 사용

- 백엔드 의존성에 `Pillow==13.0.0`이 추가되었습니다. 최초 설치는 3절의 `requirements.lock.txt` 설치 절차를 따릅니다. 기존 환경에서는 backend 가상환경에 `python -m pip install -r requirements.lock.txt`를 적용한 뒤 같은 터미널에서 서버를 재시작합니다. 키 출력이나 DB 초기화 명령은 필요하지 않습니다.
- `/submit`에서 **텍스트 작품 / 사진 작품**을 선택합니다. 사진은 선택·미리보기·변경·선택 취소가 가능하고, 기증 버튼을 눌러야 서버로 전송됩니다. 전송 중에는 ‘사진 업로드 취소’로 중단할 수 있고 입력/선택은 유지합니다. 서버에 이미 도착한 미기증 파일은 비공개 만료 정책을 따릅니다. 기존 AI 회화 메뉴는 별도 기존 기능으로 유지하며 사진 화풍 변환 메뉴는 제공하지 않습니다.
- JPG/JPEG·PNG·WEBP 정지 이미지, 최대 **5 × 1024 × 1024바이트**를 받습니다. 추가 디코딩 안전 한도는 **4천만 화소**입니다. GIF·SVG·실행 파일·움직이는 PNG/WEBP·손상 파일·확장자/실제 형식이 다른 파일은 거절합니다.
- 서버는 [Pillow의 검증 및 디코딩](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.verify)으로 파일을 확인합니다. 저장 시에는 리사이즈·재인코딩하지 않고 메타데이터를 포함한 원본 바이트를 유지합니다.
- 사진 작품 수정에서 새 파일을 고르지 않으면 기존 사진이 유지됩니다. 새 파일은 저장 성공 후 교체되고, 선택 취소는 기존 사진을 지우지 않습니다. 설명 원문 `content`와 확인된 큐레이터 설명 `refined_description`은 계속 분리합니다.

### API·저장 구조

| API | 동작 |
| --- | --- |
| `POST /api/photo-uploads` | 원본 파일을 요청 본문으로 전송. `Content-Type`, URL 인코딩한 `X-File-Name`, UUID4 `X-Visitor-ID`/`X-Upload-ID`, 브라우저가 만든 임시 `X-Upload-Token` 헤더 사용. 201(최초)/200(동일 업로드 재확인)과 `photo_token`, 만료 시각·MIME·크기 반환 |
| `POST /api/artworks` | 기존 JSON 필드에 `photo_token`만 추가해 검증된 사진 연결. 사진과 AI 이미지 토큰의 동시 제출은 거절 |
| `PUT /api/artworks/{id}` | 기존 본인 작품 검증 유지. 사진 작품에서만 선택적인 새 `photo_token`으로 교체 가능 |
| `GET /api/artworks/{id}/image` | 현재 공개 작품에 연결된 원본만 반환. 저장 해시 확인·정확한 MIME·nosniff·no-store 적용 |
| `DELETE /api/artworks/{id}` | 기존 본인 작품 검증 후 DB·좋아요 삭제. DB 커밋 이후 해당 사진 파일 정리 |

파일 본문을 직접 전송하므로 별도 multipart 라이브러리는 추가하지 않습니다. 업로드 헤더의 토큰은 임시 파일 연결용이며 API 키나 정식 인증 수단이 아닙니다. URL에 토큰을 넣거나 브라우저에서 내부 저장 경로를 사용하지 않습니다.

- 기존 `uploads/paintings`와 같은 루트의 **`uploads/photos/<무작위 UUID>.<jpg|png|webp>`**에 저장합니다. 테스트는 `EXCUSE_ME_PHOTO_DIR`로 임시 폴더를 지정합니다. `.env`는 변경하지 않습니다.
- 기존 작품 테이블의 `image_mode`/`image_url`을 재사용합니다. 응답의 `artwork_type`은 text/photo이며 기존 AI 작품은 generated로 유지합니다. 기존 텍스트 작품은 `image_mode=NULL` 그대로이며 응답에서 text로 구분합니다.
- `photo_uploads`(검증·소유자·토큰 해시·파일명·해시·기증 연결·만료·상태)와 `photo_cleanup`(정리 재시도) 테이블만 추가합니다. 기존 작품 컬럼·행을 삭제하거나 초기화하지 않습니다. DB에는 내부 절대 경로를 저장하지 않습니다.
- 업로드만 성공한 사진은 비공개이며 24시간 동안 기증/교체할 수 있습니다. 응답 유실 재시도는 같은 ID·토큰·파일로 중복 저장을 막습니다. 최종 작품 저장이 실패하면 입력·사진 선택·임시 파일을 유지해 재시도할 수 있습니다.

### 교체·삭제와 정리 실패

교체/삭제의 DB 트랜잭션이 끝나기 전에는 기존 사진을 지우지 않습니다. DB 실패 시 연결과 좋아요가 롤백되어 기존 파일을 계속 조회할 수 있습니다. 성공 후에도 활성 작품에 연결된 파일은 정리하지 않으며, 새 사진 관리 테이블에서 폐기 대상으로 기록한 안전한 파일명만 처리합니다. 기존 미등록 업로드와 AI 회화 파일은 건드리지 않습니다.

파일 잠금 등으로 물리 삭제만 실패하면 DB 결과를 되돌리거나 성공한 요청을 실패로 처리하지 않습니다. 정리 작업을 DB에 남기고 `X-Photo-Cleanup: pending`으로 알리며 브라우저도 안내합니다. 서버 시작·다음 사진 작업·작품 삭제에서 다시 시도합니다. 만료된 미기증 사진도 같은 방식으로 정리합니다. 권한/파일 잠금이 계속되면 원인을 해소한 뒤 서버를 재시작해야 합니다.

### 검사와 직접 확인

백엔드 **80개**, 프론트엔드 **57개** 자동 검사와 빌드를 통과했습니다. 정상 JPG/PNG/WEBP, 크기·형식·손상 거절, 등록/수정/교체/삭제·좋아요·순위·랜덤과 DB/디스크 실패 검사는 임시 DB·임시 이미지 폴더만 사용했습니다. 전송 취소와 저장 후 사진 파일 누락·손상도 검사했습니다.

실제 브라우저는 미검증입니다. 테스트용 사진으로 선택 취소 → 기증 → 상세/목록/명예의 전당/랜덤 → 제목만 수정해 사진 유지 → 사진 교체 → 테스트 작품 삭제를 확인하세요. 모바일 비율·잘못된 파일 안내·실패 후 선택 유지도 확인해야 합니다. 기존 사용자 작품이나 이미지로 삭제 테스트를 하지 않습니다.
