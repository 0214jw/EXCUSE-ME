# EXCUSE ME!

일상 속 황당하고 창의적인 핑계를 예술 작품처럼 등록하고 감상하는 참여형 디지털 박물관.

**Phase 1.5 설치미술 히어로와 Phase 2 텍스트 작품 기증·SQLite 저장·목록/상세 조회를 구현했습니다.** 상세 감상실·확장 필드에 이어 사진 미리보기와 사진/AI 제작 방식·화풍 선택 UI를 준비했습니다. 백엔드 테스트 **15개**, 프론트엔드 테스트 **16개**, 빌드가 통과했습니다. 사용자가 브라우저에서 사진 미리보기·방식/화풍 선택·이미지 기증 차단·텍스트 기증을 확인했으며, 나머지 미검증은 아래에 구분합니다. 실제 사진 서버 업로드·AI 생성/변환·수정/삭제·투표는 미구현입니다. 이번 저장 메시지는 `feat: Phase 2 작품 등록 및 제작 방식 선택 UI 구현`이며 최종 커밋·푸시 결과는 Git 기록과 작업 완료 보고로 확인합니다. 자세한 이력은 [PROGRESS.md](docs/PROGRESS.md)를 참고합니다.

## 1. 폴더 구성


## 4. 실행하기: 터미널 두 개 사용

### 터미널 1 — 백엔드

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\backend"
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

서버가 실행되는 동안 이 터미널은 켜 둡니다. 브라우저에서 <http://127.0.0.1:8000/api/health>를 열면 `{"status":"ok"}`가 표시됩니다. 자동 API 문서는 <http://127.0.0.1:8000/docs>입니다.

### 터미널 2 — 프론트엔드

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\frontend"
npm.cmd run dev
```

브라우저에서 **<http://localhost:5173>**을 열면 랜딩페이지가 표시됩니다. **전시 관람하기**로 <http://localhost:5173/gallery>에 이동합니다. 서버 연결 테스트는 하단 **서버 연결 확인** 링크 또는 **<http://localhost:5173/health>**에서 실행합니다.

두 서버는 각각 해당 터미널에서 `Ctrl+C`로 종료합니다. 다시 실행하려면 같은 실행 명령을 입력합니다. 현재 명령은 코드 변경 후 자동 재시작을 설정하지 않으므로, 백엔드 코드를 고쳤다면 종료 후 다시 실행합니다.

프론트엔드 포트는 `5173`으로 고정했고, 사용 중이면 다른 포트로 자동 이동하지 않고 오류를 표시합니다. 포트가 이미 사용 중일 때는 기존에 실행한 서버인지 확인하고 그 터미널에서 종료한 뒤 다시 실행합니다.

## 5. 서버 주소 설정

기본 서버 주소는 `http://127.0.0.1:8000`이며 `.env` 없이 실행할 수 있습니다. 변경이 필요할 때만 다음 명령으로 예시를 복사합니다.

```powershell
Set-Location "C:\Users\aicam\Desktop\EXCUSE ME\frontend"
Copy-Item .env.example .env
```

생성한 `.env`의 `VITE_API_BASE_URL`을 변경하고 프론트엔드를 재시작합니다. 이미 `.env`가 있다면 복사 명령으로 덮어쓰지 말고 기존 파일을 편집합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀번호나 API 키를 넣지 않습니다.

FastAPI는 `http://localhost:5173`과 `http://127.0.0.1:5173`에서 오는 GET·POST와 JSON Content-Type을 허용합니다. 이 설정을 CORS라고 하며, 다른 주소의 화면이 서버 응답을 읽을 수 있는지 브라우저에 알려줍니다. 프론트엔드 포트를 바꾸면 `backend/main.py`의 허용 주소도 함께 바꿔야 합니다.

## 6. 연결 확인 화면에서 직접 확인할 동작

1. 두 서버를 켜고 <http://localhost:5173/health>를 엽니다. 연결 확인 화면의 제목과 버튼이 보이는지 확인합니다.
2. **서버 연결 확인**을 누르면 **연결 성공**과 `{"status":"ok"}`가 표시되어야 합니다.
3. 백엔드 터미널에서 `Ctrl+C`를 누릅니다. 프론트엔드 터미널은 유지합니다.
4. 같은 버튼을 다시 누르면 **연결 실패**와 백엔드 실행 여부를 확인하라는 안내가 표시되어야 합니다. 이전 성공 응답은 사라져야 합니다.
5. 백엔드를 같은 명령으로 다시 실행하고 버튼을 누르면 다시 성공해야 합니다.
6. 두 터미널에서 각각 `Ctrl+C`로 종료한 뒤 다시 실행해 봅니다.

연결 요청 중에는 버튼이 비활성화되고 **연결 확인 중…**을 표시합니다. 5초 안에 응답을 받지 못하면 시간 초과 안내를 표시하도록 구현했습니다. 연결 상태는 마지막 버튼 클릭 시점의 결과이며 자동 감시 기능은 없습니다.

## 9. DB·방문객 ID·API

서버를 처음 실행하면 프로젝트의 `database/excuse_me.sqlite3`에 작품 테이블을 생성합니다. 제목·내용·카테고리·작가명·방문객 ID·작품 ID·등록일·수정일과 재시도 구분용 요청 ID를 저장합니다. DB는 파일에 남아 서버를 껐다 켜도 유지됩니다. 서버의 작업 폴더를 바꿔도 기본 DB 경로는 같습니다. 등록·수정일은 UTC로 저장하고 화면은 한국 시간으로 표시합니다. 수정 기능은 아직 없습니다.

실제 DB와 저널 파일은 `.gitignore`로 제외됩니다. DB 구조는 `backend/database.py`에서 재현합니다. 테스트나 별도 저장소가 필요하면 서버 실행 전에 `EXCUSE_ME_DB_PATH` 환경변수에 원하는 파일 경로를 지정할 수 있습니다. 일반 실행에서는 지정할 필요가 없습니다.

최초 방문 시 UUID v4를 브라우저 localStorage의 `excuse-me.visitor-id`에 저장합니다. 새로고침·재방문 시 유지되지만 다른 브라우저·기기·origin은 별개입니다. 예를 들어 `localhost:5173`과 `127.0.0.1:5173`은 저장소를 공유하지 않습니다. 저장소를 사용할 수 없으면 조회는 가능하지만 기증은 입력을 유지하며 오류를 안내합니다.

**이 방문객 ID는 실제 인증 수단이 아닙니다.** 사용자가 복사·변경할 수 있으므로 보안이 필요한 권한을 보장하지 않습니다. 작가명도 인증 정보가 아닙니다. 저장소를 지우면 이전 ID를 잃을 수 있으며 ID 복구는 제공하지 않습니다. API의 공개 조회 응답에는 방문객 ID와 요청 ID를 노출하지 않습니다.

| API | 동작 |
| --- | --- |
| `GET /api/health` | 기존 `{"status":"ok"}` 응답 |
| `POST /api/artworks` | JSON `title`, `content`, `category`, 선택 `author`, UUID v4 `visitor_id`, 선택 UUID v4 `request_id`. 신규 저장은 201과 작품·Location 반환 |
| `GET /api/artworks` | 작품 배열, 최신 등록순, 같은 등록 시각이면 ID 내림차순. 빈 DB는 `[]` |
| `GET /api/artworks/{id}` | 작품 단건, 없는 작품 404, 잘못된 ID 422 |

입력 오류는 422와 `errors`의 항목별 안내, DB 오류는 503입니다. 내부 DB 경로나 원본 입력값을 오류 응답에 그대로 포함하지 않습니다. 수정·삭제 API는 없습니다.

기증 중에는 입력과 제출 버튼을 잠그고 중복 실행을 막습니다. 같은 화면에서 같은 입력을 다시 기증하면 동일한 `request_id`를 재사용하고 서버는 기존 작품을 200으로 반환합니다. 같은 방문객·요청 번호에 다른 내용을 보내면 409입니다. API를 직접 호출하면서 `request_id`를 생략하면 서버가 새 번호를 만들므로 재시도 중복 방지를 원하면 같은 번호를 전달해야 합니다.

응답이 없거나 서버 오류가 나면 저장됐을 가능성도 함께 안내하고 자동 재시도하지 않습니다. 화면에 입력은 유지되며 직접 재시도할 수 있습니다. 새로고침·화면 이탈 뒤에는 입력과 재시도 키를 보존하지 않으므로 불확실한 결과는 전시관에서 확인하세요.

## 11. 상세 감상실 확장 준비

백엔드를 다시 실행하면 기존 테이블에 `refined_description`, `image_url`, `image_mode`, `image_style` 선택 컬럼만 자동 추가됩니다. 기존 작품과 원문 `content`, 작품 번호·방문객 정보·등록일은 보존됩니다. 기존 작품의 새 필드는 NULL이며 테이블을 재생성하지 않습니다. 코드 검사에서는 실제 DB의 임시 복제본으로도 보존을 확인했습니다.

상세 화면 왼쪽은 액자와 이미지 자리, 오른쪽은 작품명·작가명·작품 설명·기증 날짜·카테고리·기증 버튼 순서입니다. 이미지가 없으면 **작품 이미지는 준비 중입니다.**, 별도 설명이 없으면 원문을 포함한 **임시 설명**을 표시합니다. 임시 설명을 DB에 저장하거나 원문을 덮어쓰지 않습니다. 작은 화면은 이미지 위·정보 아래로 배치합니다.

향후 서버의 별도 GPT 처리 결과는 `refined_description`, 이미지 처리 결과는 `image_url`과 `image_mode`(`generated` / `photo`)·`image_style`(`watercolor`, `oil`, `pointillism`, `pencil`, `collage` 등)에 연결할 수 있습니다. `photo`는 향후 사진을 원본으로 하는 경로를 위한 값입니다. 결과 저장·검증용 서버 기능은 이후에 추가해야 하며 현재 기증 API는 이 필드 입력을 받지 않습니다. 화면의 `ArtworkExhibition.jsx`·`artworkPresentation.js`는 조회된 필드로 표시만 처리합니다.

실제 GPT·이미지 API, 사진 업로드·화풍 변환, 이미지 서빙은 구현하지 않았습니다. 임시 설명은 고정 문장과 원문을 조합한 표시이며 GPT 결과가 아닙니다. 새 상세 화면도 브라우저 배치·이미지 로드 실패·기증 버튼 클릭은 미검증입니다. 기존 작품 또는 새로 기증한 작품을 열어 정보 순서·이미지 준비 안내·임시 설명·모바일 배치를 직접 확인해 주세요.
