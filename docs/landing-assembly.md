# 랜딩 작품 집결 인터랙션 참고 상태

## 현재 확대 규격 — 2026-11-09 재조정

- 같은 Hero의 전시 장면을 100svh(최소 720px)로 확대합니다. 데스크톱에서 장면 전체가 viewport에 들어갈 때만 sticky를 사용하며 추가 스크롤 100vh를 더해 전체 인터랙션은 약 200vh입니다. 기존 정보와 두 CTA는 장면 뒤의 일반 흐름으로 이어져 장면을 압축하지 않습니다.
- 상단 EXCUSE ME!는 15.8cqw·900·line-height 0.9·기존 버건디로 표시합니다. 전시 영역 상단 8px에 왼쪽 정렬하며 1440px 화면에서는 약 216px입니다. BrandIntro의 크기·배경·오른쪽 정렬·헤더는 변경하지 않습니다.
- 조각상은 기존 PNG 그대로 높이 62svh(1440×900 기준 558px), 폭 min(48vw,740px), max-height는 전시 영역 높이 - 100px입니다. object-fit: contain을 유지합니다.
- 실제 작품은 최대 4점입니다. 폭 clamp(120px,14vw,280px)·3:4이며 1440px 화면에서는 약 202×269px입니다. 이동 중 크기는 바뀌지 않습니다. Gallery의 이미지/텍스트 포스터를 재사용하며 Hero 내부의 포스터 글자도 확대합니다.
- 넓은 전시 영역(가로/세로 비율 1.65 이상)에서 초기 중심 좌표는 (4%,34%), (15%,82%), (85%,34%), (96%,82%)입니다. 작품 실제 크기를 반영해 가장자리에서 최소 8px을 확보하도록 보정합니다. 최종 x는 9%,26.5%,73.5%,91%, y는 64%로 조각상 좌우 2점씩 한 줄에 정렬합니다.
- 좁은 데스크톱에서는 작품을 축소하지 않고 좌우 2단으로 배치합니다. 초기 x는 8%,5%,92%,95%, y는 34%/82%; 최종 x는 17%/83%, y는 45%/80%입니다. 작품 레이어는 전시 벽과 타이포/조각상 뒤에 둡니다.
- 진행도는 clamp(-실제 구간 상단 / viewport 높이,0,1)에 smoothstep을 적용합니다. sticky 상단은 0이며 실제 헤더 높이는 장면 내부의 여백으로 확보합니다. 헤더 자체의 전환은 변경하지 않습니다. 짧은 화면은 sticky와 추가 거리를 없앱니다.
- 모바일(800px 이하)은 최대 2점, 폭 clamp(90px,28vw,200px), 3:4입니다. 장면 최소 높이 900px로 큰 조각상과 작품을 압축하지 않고 자연스럽게 스크롤합니다. 작품은 하단 x 22%/78%에 정렬하며 가로 이동·회전 없이 세로 48px/36px만 이동합니다. 조각상은 최대 60svh 안에서 작품 공간을 확보합니다.
- reduced-motion은 이동·회전·추가 sticky 구간 없이 최종 상태를 바로 표시합니다. 키보드 접근 시에도 최종 상태를 표시합니다. 작품이 없거나 조회 실패 시 추가 구간 없이 큰 조각상 Hero를 표시합니다.
- 프론트엔드 전체 72개 테스트와 빌드가 통과했습니다. 여러 크기에서 시작/종료 좌표의 영역 이탈, 조각상 중앙 공간, 2단 배치, 모바일·역방향·resize·접근성·기존 CTA/헤더 회귀를 검사했습니다. 실제 브라우저의 최종 시각 검증은 미검증입니다.
- 이번 조정 전후 BrandIntro·헤더·Gallery·상세·백엔드·조각상 원본·실제 DB·uploads의 해시가 같습니다. AI 호출과 Git commit/push는 하지 않았습니다. Figma는 이번 조정에서 수정하지 않았습니다.

아래의 5점·작은 전시 줄·150vh 수치는 과거 기록입니다. 현재 구현은 위 확대 규격을 따릅니다.

2026-11-09. React 구현 기준이며 Figma에는 아직 반영하지 못했습니다.
Figma Starter 플랜의 MCP 호출 한도에 도달했습니다. 기존 랜딩과 다른 Figma 화면은 변경하지 않았습니다.

## 공통 구성

- BrandIntro → HeroExhibition → Footer의 두 핵심 화면 구조를 유지합니다.
- BrandIntro·헤더의 코드와 스타일, 조각상 원본 자산·브랜드 문구·두 CTA는 유지합니다.
- Hero의 기존 장식 포스터 2개를 제거하고 Gallery와 같은 GET /api/artworks 응답의 최신 5점을 사용합니다. 같은 등록일이면 ID 내림차순인 기존 API 정렬을 따릅니다.
- 첫 조회에서는 9점 중 ID 11, 10, 9, 8, 5가 선택됐습니다. 검증 도중 외부 요청으로 작품 1점이 추가되어 마지막 조회에서는 10점 중 ID 12, 11, 10, 9, 8이 선택됐습니다. 두 경우 모두 이미지 2점·텍스트 3점입니다. 에이전트가 실제 서버에 보낸 요청은 목록 GET뿐이며 작품 생성·수정·삭제 요청은 보내지 않았습니다. 이후 기증·삭제 시 API 결과에 따라 대상이 달라집니다.
- ArtworkVisual의 Gallery 모드(3:4 cover 이미지/텍스트 포스터)를 재사용합니다. 액자·테두리·그림자는 없습니다. 작은 전시 크기에 맞춘 글자 크기만 Hero 내부에 한정해 조정합니다.

## 참고 상태 1 — 흩어진 작품

아래 좌표는 Hero 전시 벽을 기준으로 한 작품 중심 위치입니다. 무작위 값은 사용하지 않습니다.

| API 순서 | 가로 위치 | 세로 위치 | 회전 |
| --- | --- | --- | --- |
| 1 | 12% | 34% | -4° |
| 2 | 24% | 68% | 3° |
| 3 | 87% | 32% | 4° |
| 4 | 78% | 66% | -3° |
| 5 | 34% | 46% | -2° |

작품은 불투명도 0.8에서 시작합니다. 배경·BrandIntro·Hero 전체를 fade하거나 gradient로 연결하지 않습니다.

## 참고 상태 2 — 정렬된 작품

- 조각상 바로 아래, 설명/CTA 바로 위에 최대 5점을 가로 한 줄로 중앙 정렬합니다.
- 작품 폭은 clamp(64px, 8vw, 104px), 작품 사이 간격은 clamp(12px, 2vw, 24px)입니다.
- CSS flex로 중심 높이와 간격을 맞춥니다. 모든 이동·회전은 0, 불투명도는 1로 끝납니다.
- 작품은 z-index 1, 기존 전시 벽과 조각상·타이포는 그 위 z-index 2의 별도 stacking context로 보호합니다. 최종 줄은 조각상 아래에 있어 얼굴을 가리지 않습니다.
- 기존 전시 관람하기(/gallery)·작품 기증하기(/submit) 버튼은 그대로 사용합니다. 작품은 기존 상세 주소로 연결됩니다.

## 스크롤과 반응형

- Hero가 헤더 아래에 닿으면, 화면에 Hero 전체가 들어가는 데스크톱에서만 sticky를 사용합니다.
- 구간 높이는 실제 Hero 높이 + viewport 높이의 50%입니다. Hero가 화면 안에 들어오는 조건이므로 전체 구간은 최대 약 150vh입니다.
- 진행도는 clamp((헤더 높이 - Hero 구간 상단) / 추가 스크롤 거리, 0, 1)이며 smoothstep으로 시작과 끝을 부드럽게 합니다. 역방향 스크롤에도 같은 식을 사용합니다.
- 높이가 부족하거나 폭이 800px 이하이면 sticky와 추가 구간을 없앱니다. Hero가 viewport에 들어오는 실제 위치를 기준으로 짧게 진행합니다.
- 모바일은 앞의 최대 3점만 표시합니다. 가로 이동·회전 없이 세로 -28/+24/-18px에서 최종 줄로 이동합니다. 전시 영역 바깥 그림은 clip으로 제한합니다.
- prefers-reduced-motion에서는 sticky·추가 스크롤·transform을 생략하고 최종 정렬 상태를 바로 표시합니다. 키보드로 작품에 접근해도 최종 상태를 표시합니다.
- 작품이 없거나 조회 실패/로딩 중이면 작품 줄·추가 스크롤 없이 조각상 Hero와 CTA를 표시합니다.
- passive scroll + requestAnimationFrame으로 프레임당 한 번만 진행도를 갱신합니다. React 상태를 매 스크롤마다 바꾸지 않습니다. ResizeObserver는 Hero와 실제 헤더 높이 변화를 재측정합니다.

## 검증과 남은 확인

- 프론트엔드 전체 테스트 71개 통과, 빌드 성공. 데이터 개수·원본 불변·진행도·역방향·프레임 병합·모바일·낮은 화면·motion preference 변경·정리·공통 전시 컴포넌트 재사용을 검사했습니다.
- 백엔드·BrandIntro·헤더·Gallery·상세 소스와 uploads는 기준 해시와 같습니다. 실제 DB 파일은 검증 중 작품 1점이 추가되어 해시가 달라졌으며 외부 변경을 되돌리지 않았습니다. 에이전트는 DB 쓰기를 수행하지 않았습니다.
- 브라우저 제어 도구가 현재 URL을 확인하지 못해 중단됐으므로 실제 화면의 겹침·스크롤 체감·브라우저별 성능은 미검증입니다.
- 데스크톱/모바일에서 초기 배치, 최종 가로 줄, 조각상 얼굴, 두 CTA, 위로 복귀, 가로 overflow와 Footer 진입을 직접 확인해야 합니다.
- Figma에는 기존 랜딩을 보존하고 초기/최종 Hero 참고 프레임 2개만 추가하면 됩니다. 위 표와 React의 실제 전시 줄을 기준으로 편집 가능한 작품 레이어를 배치합니다. 현재 Figma 반영 완료로 간주하지 않습니다.
