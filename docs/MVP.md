# EXCUSE ME! MVP

**현재 상태(2026-11-05): 랜덤 작품 감상(F08)은 서비스에서 제거되었습니다.** `/random` 화면·메뉴·진입 버튼은 제공하지 않습니다. 이 문서의 F08과 관련 랜덤 흐름은 초기 기획 이력이며 현재 서비스의 요구사항·브라우저 검증 대상에서 제외합니다. 백엔드 호환 API는 이번 제거 범위에 포함하지 않았습니다.

## 1. 서비스와 첫 버전의 목표

EXCUSE ME!는 일상 속 황당하고 창의적인 핑계를 예술 작품처럼 등록하고 감상하는 참여형 디지털 박물관입니다.

주요 사용자는 짧고 재미있는 콘텐츠를 즐기고 자신의 경험을 재치 있게 공유하고 싶은 LG AX 1기 부트캠프 사람들입니다.

핵심 메시지는 **“Every Excuse Deserves an Exhibition.” / “모든 핑계에는 전시될 자격이 있다.”**입니다. 텍스트 작품을 기반으로 사용자가 직접 촬영한 사진전과 핑계 기반 AI 회화전으로 확장합니다.

개발 범위는 두 완료 지점과 후속 확장으로 구분합니다. **기본 MVP**는 기존 텍스트 기증·감상·투표(F01~F08), 설치미술 히어로(F09), 작가명 입력(F10의 공통 부분)입니다. **사진 포함 MVP**는 여기에 단일 이미지 방식 선택(F10), 사진전(F11), 텍스트·사진 통합 감상(F13)을 더한 이번 개정의 MVP 목표입니다. **AI 회화전(F12)과 F13의 AI 통합은 사진 포함 MVP가 완성된 뒤 진행할 확장 기능**이며 MVP 완료 조건이 아닙니다.

기존 1~2주 목표는 텍스트 중심 기본 MVP의 초기 가정입니다. 히어로 제작·사진 업로드가 추가된 전체 일정은 **확인 필요**이며 같은 기간 안의 완료를 약속하지 않습니다.

| 일반적인 게시판 표현 | 서비스에서 사용하는 표현 |
| --- | --- |
| 게시글 작성 | 작품 기증 |
| 게시글 목록 | 상설 전시관 |
| 게시글 상세 | 작품 감상실 |
| 좋아요 | 명작 인정 |
| 인기 게시글 | 명예의 전당 |

개발에 사용할 기술은 React, Tailwind CSS, Python FastAPI이며, 초기 데이터 저장에는 SQLite를 사용합니다. 이 문서는 기능 범위와 완료 기준을 정하며, 코드 작성과 패키지 설치는 포함하지 않습니다.

## 2. 작품과 방문객의 기본 규칙

### 작품 정보와 카테고리

- 작품을 기증할 때 작품명(기존 제목과 같은 항목), 핑계 내용, 카테고리 한 가지와 작가명을 입력합니다. 작가명 필수 여부·빈 값·길이 정책은 **확인 필요**입니다. 표시용 작가명은 소유권 확인용 방문객 ID를 대신하지 않습니다.
- 제목과 내용은 공백만 입력할 수 없습니다.
- 카테고리는 **지각, 과제, 약속, 운동, 기타** 다섯 가지로 제한합니다.
- 작품 번호, 등록 시각, 기증한 방문객 ID는 서비스가 자동으로 기록합니다.
- 명작 인정 수는 해당 작품에 남아 있는 투표의 개수입니다.
- 기본 MVP의 등록·DB 단계는 이미지 없는 텍스트 작품으로 먼저 완성합니다. 기존 텍스트 작품은 이후에도 보존하고 감상할 수 있게 합니다.
- 사진 포함 MVP의 이미지 기증에서는 **사진 업로드하기 / AI로 작품 만들기** 중 하나의 방식을 선택하는 구조를 사용합니다. AI 확장 전에는 사진만 실제로 이용할 수 있고 AI 선택지는 준비 중으로 구분합니다.
- 하나의 이미지 작품에 사진 업로드와 AI 생성 방식을 동시에 적용하지 않습니다. 최종 이미지 개수와 교체·재생성 정책은 **확인 필요**입니다.
- 상황 카테고리(지각·과제·약속·운동·기타)와 전시 유형(사진전·AI 회화전)은 서로 다른 분류입니다. 전체 전시관은 기존 텍스트와 활성화된 이미지 유형을 함께 보여줍니다.

### 브라우저별 데모 방문객 ID

- 정식 회원가입과 로그인은 제공하지 않습니다.
- 처음 방문할 때 임의의 데모 방문객 ID를 만들고 브라우저에 저장합니다.
- 같은 브라우저의 저장 정보가 유지되면 새로고침하거나 다시 방문해도 같은 ID를 사용합니다.
- 이 ID를 기준으로 본인 작품과 투표 여부를 구분합니다.
- 다른 브라우저나 기기를 사용하면 별도의 방문객으로 취급합니다. 같은 브라우저를 함께 쓰면 같은 방문객으로 취급될 수 있습니다.
- 브라우저 저장 정보를 삭제하거나 시크릿 창을 이용하면 기존 ID를 계속 사용할 수 없습니다. 기존 작품은 남아 있어도 본인 작품으로 수정하거나 삭제할 수 없게 될 수 있습니다. 첫 버전에는 ID 복구 기능이 없습니다.

**한계:** 데모 방문객 ID는 실제 사용자 인증을 대신할 수 없습니다. 브라우저에 저장된 ID는 사용자가 변경하거나 복사할 수 있어 다른 사람을 흉내 내거나 여러 ID로 투표할 수 있습니다. 따라서 본인 작품 구분과 중복 투표 제한은 데모 수준이며, 실제 사람 한 명당 한 표를 보장하지 않습니다. 공개 서비스로 확장할 때는 정식 인증과 권한 확인이 필요합니다.

## 3. 필수 기능과 완료 기준

### 1. 박물관 랜딩페이지 (F01)

**필요한 이유**

처음 방문한 사람이 서비스의 주제와 참여 방법을 빠르게 이해하고 전시관으로 들어갈 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- EXCUSE ME!의 소개와 핑계 작품 예시를 읽습니다.
- 상설 전시관, 작품 기증, 명예의 전당으로 이동합니다.
- 랜덤 작품 감상을 시작합니다.

**완료 기준**

- 서비스 이름, 짧은 소개, 회원가입 없이 참여하는 데모라는 안내가 보입니다.
- 각 이동 버튼을 누르면 해당 화면이나 기능으로 연결됩니다.
- 휴대전화와 PC에서 주요 글과 버튼이 잘리지 않고 보입니다.

### 2. 핑계 작품 등록 — 작품 기증 (F02)

**필요한 이유**

방문객의 경험이 새로운 전시 작품이 되어야 박물관의 콘텐츠가 쌓입니다.

**사용자가 할 수 있는 행동**

- 작품명과 핑계 내용을 작성하고 카테고리와 작가명을 입력합니다. 이미지 기증 단계에서는 F10의 방식 선택을 이어서 사용합니다.
- 작품 기증 버튼을 눌러 등록합니다.
- 입력이 잘못되거나 등록에 실패하면 안내를 확인하고 다시 시도합니다.

**완료 기준**

- 제목, 내용, 카테고리가 모두 올바를 때만 등록됩니다.
- 비어 있거나 공백뿐인 제목·내용, 정해진 다섯 가지 외의 카테고리는 등록되지 않고 이유가 표시됩니다.
- 등록된 작품에 현재 방문객 ID가 연결됩니다.
- 등록 성공 후 새 작품의 감상실로 이동하고, 상설 전시관에서도 확인할 수 있습니다.
- 새로고침해도 등록한 작품이 남아 있습니다.

### 3. 작품 목록 및 상세 조회 — 상설 전시관과 작품 감상실 (F03)

**필요한 이유**

여러 작품을 쉽게 둘러보고 마음에 드는 작품의 전체 내용을 읽을 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 상설 전시관에서 작품 목록을 봅니다.
- 작품을 선택해 감상실로 이동합니다.
- 감상 후 목록으로 돌아갑니다.

**완료 기준**

- 목록은 최근에 등록된 작품부터 보여줍니다.
- 목록에서 작품 제목, 카테고리, 명작 인정 수를 확인할 수 있습니다.
- 감상실에서 작품 번호, 제목, 전체 내용, 카테고리, 등록 시각, 명작 인정 수를 확인할 수 있습니다.
- 작품이 없으면 아직 기증된 작품이 없다는 안내와 작품 기증 버튼이 보입니다.
- 존재하지 않거나 삭제된 작품의 주소에 접속하면 안내와 전시관으로 돌아가는 버튼이 보입니다.

### 4. 카테고리별 필터링 (F04)

**필요한 이유**

방문객이 관심 있는 상황의 핑계를 빠르게 찾아볼 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 상설 전시관에서 전체, 지각, 과제, 약속, 운동, 기타 중 하나를 선택합니다.
- 전체를 선택해 모든 작품을 다시 봅니다.

**완료 기준**

- 처음에는 전체 작품이 보입니다.
- 카테고리를 선택하면 해당 카테고리의 작품만 보이며, 최근 등록순을 유지합니다.
- 현재 선택한 항목을 화면에서 구분할 수 있습니다.
- 해당 카테고리의 작품이 없으면 결과가 없다는 안내가 보입니다.

### 5. 본인 작품 수정 및 삭제 (F05)

**필요한 이유**

기증자가 오타를 고치거나 더 이상 공개하고 싶지 않은 작품을 내릴 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 본인 작품의 감상실에서 수정 또는 삭제를 선택합니다.
- 제목, 내용, 카테고리를 수정해 저장합니다.
- 삭제 확인 안내에서 삭제를 진행하거나 취소합니다.

**완료 기준**

- 작품에 기록된 방문객 ID와 현재 방문객 ID가 같을 때만 수정·삭제 버튼이 보입니다.
- 서버에서도 두 ID를 비교하며, 일치하지 않는 ID로 보낸 수정·삭제 요청은 거절합니다. 단, 이 비교는 앞서 설명한 데모 ID의 한계를 가집니다.
- 수정에도 작품 등록과 같은 입력 규칙을 적용합니다.
- 수정한 내용은 새로고침 후에도 유지되며, 기존 명작 인정 수는 유지됩니다.
- 삭제를 취소하면 작품이 그대로 남습니다.
- 삭제를 확정하면 작품과 연결된 투표가 제거되고, 목록·상세·명예의 전당·랜덤 감상에서 더 이상 나타나지 않습니다.
- 첫 버전에는 삭제한 작품을 복구하는 기능이 없습니다.

### 6. 작품별 명작 인정 투표 및 취소 (F06)

**필요한 이유**

방문객이 공감을 간단하게 표현하고, 인기 작품을 정할 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 작품 감상실에서 명작 인정 버튼을 눌러 투표합니다.
- 이미 투표한 버튼을 다시 눌러 투표를 취소합니다.
- 현재 투표 수와 본인의 투표 여부를 확인합니다.

**완료 기준**

- 하나의 방문객 ID는 작품 하나에 한 표만 유지할 수 있습니다.
- 투표하면 수가 1 증가하고, 취소하면 1 감소합니다.
- 버튼을 빠르게 여러 번 눌러도 같은 방문객의 표가 중복 저장되거나 투표 수가 음수가 되지 않습니다.
- 새로고침해도 투표 수와 해당 방문객의 투표 여부가 유지됩니다.
- 투표 또는 취소 후 목록과 명예의 전당을 다시 조회하면 변경된 수가 반영됩니다.

### 7. 투표 수 기반 명예의 전당 TOP 10 (F07)

**필요한 이유**

공감을 많이 받은 작품을 모아 보여주어 처음 방문한 사람도 인기 작품을 쉽게 발견할 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 명예의 전당에서 상위 작품의 순위와 명작 인정 수를 확인합니다.
- 작품을 선택해 감상실로 이동합니다.

**완료 기준**

- 현재 명작 인정 수가 많은 순서로 최대 10개 작품이 보입니다.
- 투표 수가 같으면 등록 시각이 최근인 작품을 먼저 보여주며, 등록 시각도 같으면 작품 번호가 큰 작품을 먼저 보여줍니다.
- 작품이 10개보다 적으면 있는 작품만 표시하고, 작품이 없으면 안내 문구가 보입니다.
- 투표, 투표 취소, 작품 삭제 후 다시 조회하면 순위가 갱신됩니다.
- 별도의 운영자 선정이나 수동 등록 없이 투표 수로 순위를 정합니다.

### 8. 랜덤 작품 감상 (F08) — 제거됨 (2026-11-05)

**필요한 이유**

방문객이 작품을 직접 고르지 않아도 우연히 재미있는 작품을 만날 수 있어야 합니다.

**사용자가 할 수 있는 행동**

- 랜딩페이지에서 랜덤 작품 감상을 누릅니다.
- 작품 감상실에서 다시 랜덤 감상을 눌러 다른 작품을 찾아봅니다.

**완료 기준**

- 삭제되지 않은 전체 작품 중 하나를 무작위로 골라 감상실로 이동합니다.
- 작품이 여러 개일 때 항상 같은 작품으로 고정되지 않습니다. 무작위 선택이므로 같은 작품이 연속으로 나올 수 있습니다.
- 작품이 하나뿐이면 해당 작품을 보여줍니다.
- 작품이 없으면 안내와 작품 기증 버튼을 보여줍니다.
- 개인 취향 분석이나 추천 알고리즘은 구현하지 않습니다.

### 9. 설치미술 히어로 비주얼 (F09, 기본 MVP)

- 기존 랜딩페이지의 구조·하단 섹션·컬러 팔레트를 유지하고 히어로 비주얼 영역만 후속 작업에서 변경합니다.
- 비주얼 영역 중앙에 변명을 고민하는 인물을 입체적인 조각상 또는 설치미술처럼 표현하고 전시 받침대와 오브제를 활용합니다.
- 대표 작품명은 **그럴듯한 사유**, 문구는 **“조금만 더 생각하면, 완벽한 변명이 나올 것 같았습니다.”**, 전시명은 **The Birth of an Excuse**입니다.
- 랜딩용 대표 연출이며 실제 이용자 기증·DB 작품이나 AI 실시간 생성 결과로 표시하지 않습니다.
- PC·모바일에서 작품과 문구, 기존 이동 버튼을 사용할 수 있고 기존 하단 섹션이 유지되면 완료입니다. 에셋 제작 방식·파일 형식·오브제 세부 구성은 **확인 필요**입니다.

### 10. 작가명 및 단일 이미지 방식 선택 (F10, 단계 적용)

- 공통 기증 입력은 작품명·핑계 내용·카테고리·작가명입니다. 작가명은 화면에 표시하되 권한은 계속 방문객 ID로 판단합니다.
- 기본 MVP에서는 텍스트 저장과 작가명을 먼저 연결합니다. 사진 단계부터 이미지 방식을 선택합니다.
- 이미지 기증 방식은 **사진 업로드하기 / AI로 작품 만들기** 두 가지입니다. AI 기능 출시 전에는 AI를 실행 가능한 기능처럼 표시하지 않습니다.
- 이미지 작품 하나에 두 방식을 동시에 적용한 입력은 화면과 서버에서 거절합니다. 방식 전환 시 선택 파일·생성 결과 처리와 확인 안내는 **확인 필요**입니다.
- 선택 방식과 실제 저장 이미지의 출처가 일치하고, 미출시 AI 기능이 실행되지 않아야 완료입니다. 이미지 도입 뒤 새 텍스트 전용 기증을 별도로 계속 허용할지는 **확인 필요**이며 세 번째 선택지를 임의로 추가하지 않습니다.

### 11. 사진 업로드 및 사진전 (F11, 사진 포함 MVP)

- 사용자가 직접 촬영한 사진을 선택하고 미리보기에서 확인한 뒤 핑계 내용과 함께 기증합니다.
- 저장 성공 후 사진·작품명·작가명·핑계 내용이 목록 미리보기와 상세 감상에 표시되고 재조회 후에도 유지됩니다.
- 파일 검증과 업로드·저장 실패 안내가 있어야 하며 실패를 등록 성공으로 표시하지 않습니다.
- 파일 종류·크기·해상도·개수, 저장 위치, 공개 범위, 메타데이터 처리와 삭제 시 파일 정리 정책은 **확인 필요**입니다. 관련 필수 정책을 확정하고 테스트한 뒤 완료로 판단합니다.

### 12. AI 이미지 생성 및 AI 회화전 (F12, 추후 확장)

- 사용자가 직접 작성한 핑계와 스타일로 이미지를 생성합니다. 스타일은 **수채화, 유화, 점묘화, 연필 드로잉, 콜라주**입니다.
- 결과를 확인한 뒤 사용자가 등록을 선택해야 작품이 됩니다. 생성·미리보기만으로 자동 기증하지 않습니다.
- 비용과 실패·응답 유실을 다루고, 생성 성공과 작품 저장 성공을 구분합니다.
- 제공사·모델·예산·요청 제한·재생성·진행 취소·금지 입력·생성물 보관 정책은 **확인 필요**입니다. 승인된 비용 정책과 핵심 서비스 완료 후 별도 착수합니다.

### 13. 전체 전시관 통합 감상 (F13, 단계 적용)

- 전체 전시관에서 기존 텍스트 작품과 활성화된 사진전·AI 회화전 작품을 함께 감상합니다. AI는 F12 출시 후 포함합니다.
- 이미지 작품은 유형·이미지 미리보기·핑계·작가명을 구분하고 상세에서 이미지를 감상합니다.
- 기존 카테고리·최신 등록순 정책을 유지합니다. 유형별 화면·주소·유형 선택 UI는 **확인 필요**이며 카테고리를 전시 유형으로 대체하지 않습니다.
- 유형이 늘어도 소유자 구분·명작 인정·TOP 10 동점 규칙·삭제 제외·랜덤 정책을 유지하고 다시 테스트합니다.
- 샘플 작품과 실제 저장 작품을 구분하며 사진 단계에는 텍스트·사진, AI 단계에는 두 이미지 유형의 혼합 감상을 각각 검증합니다.

## 4. 주요 이용 흐름

1. 랜딩페이지에서 서비스 소개를 읽고 상설 전시관에 입장합니다.
2. 전체 작품을 보거나 관심 있는 카테고리로 좁혀 봅니다.
3. 작품 감상실에서 내용을 읽고 명작 인정을 누릅니다.
4. 명예의 전당이나 랜덤 감상으로 다음 작품을 발견합니다.
5. 자신의 경험을 작품으로 기증합니다.
6. 같은 방문객 ID로 본인 작품을 수정하거나 삭제합니다.

## 5. 첫 MVP에서 제외하는 기능

- 댓글과 답글
- AI 이미지 생성과 AI 회화전: 사진 포함 MVP 이후의 확장으로 분리합니다. 사진 업로드·사진전은 더 이상 MVP 제외 항목이 아닙니다.
- AI 핑계 문장 생성: 계속 제외합니다. 사용자가 작성한 핑계를 이미지로 바꾸는 F12와 구분합니다.
- 정식 회원가입과 로그인

범위가 커지지 않도록 검색, 알림, 팔로우, 개인별 추천, 별도의 관리자 화면도 첫 버전에는 포함하지 않습니다. 목록의 복잡한 정렬 옵션과 무한 스크롤도 후순위로 둡니다.

## 6. 전체 MVP의 최종 확인 기준

- 기본 MVP는 F01~F08, F09와 F10의 작가명 부분을 확인합니다. 사진 포함 MVP의 최종 완료에는 F10의 단일 방식 선택, F11과 F13의 텍스트·사진 통합까지 필요합니다. AI 관련 기준은 별도 확장 완료로 판정합니다.
- 브라우저 A에서 기증한 작품을 브라우저 B에서도 감상할 수 있고, 각 브라우저는 서로 다른 방문객으로 구분됩니다.
- 브라우저 B는 일반적인 이용 흐름에서 A의 작품을 수정하거나 삭제할 수 없으며, 두 방문객의 투표 여부도 따로 유지됩니다.
- 작품 등록·수정·삭제와 투표·취소 결과가 새로고침 후에도 유지됩니다.
- 화면을 불러오는 중임을 알 수 있고, 저장이나 조회에 실패하면 이해할 수 있는 안내를 표시합니다. 저장에 실패한 작업을 성공했다고 표시하지 않습니다.
- 휴대전화와 PC에서 작품 기증부터 감상과 투표까지 핵심 흐름을 사용할 수 있습니다.
- 데모 방문객 ID가 실제 인증이 아니며, 브라우저 저장 정보 삭제 시 본인 작품 관리 권한을 잃을 수 있다는 안내를 사용자가 볼 수 있습니다.

## 7. 개정 범위와 결정이 필요한 사항

| 기존 기준과의 충돌 | 이번 개정 |
| --- | --- |
| 텍스트 작품만 제공, 이미지 업로드 제외 | 텍스트 기반을 먼저 완성한 뒤 사진전을 MVP에 포함하고 AI 회화전은 후속 확장으로 분리 |
| 제목·내용·카테고리만 기증 입력 | 작가명을 추가하고 이미지 단계에서 단일 방식 선택을 추가. 작가명은 인증 수단이 아님 |
| 랜딩페이지의 텍스트 액자 비주얼 | Phase 1 검증·Git 저장 후 별도 히어로 단계에서 설치미술 연출로 변경. 현재 코드와 하단 섹션은 유지 |
| 샘플 인기순 정렬 | 기존 Phase 1의 샘플 전용 동작을 보존. 실제 전시관 인기순 정책이 확정된 것으로 확대하지 않음 |

현재 코드의 메인 배경은 `#F9FAFB`, 텍스트는 `#24201F`, 버건디는 `#A32632`입니다. 카드·버튼·테두리 등 기존 세부 색상도 유지 대상이며 초기 배경 `#F7F2E9`로 되돌리지 않습니다.

추가 **확인 필요** 사항은 작가명 검증·수정·기존 데이터 표시, 이미지 도입 후 신규 텍스트 전용 기증 허용 여부, 방식 전환, 업로드 제한·미디어 저장·파일 정리, 사진 권리·개인정보 안내, 이미지 수정과 기존 투표 유지의 적용 범위, 전시 유형 화면 구성, AI 제공사·비용·생성/재시도 정책입니다. 기존 글자 수·ID 방식·본인 작품 투표 등 미정 정책도 그대로 남아 있습니다.

이번 문서 개정은 구현 완료를 뜻하지 않습니다. Phase 0은 저장된 완료 기록을 유지하고, Phase 1은 현재 코드 검증과 Git 저장을 먼저 진행합니다. `PROGRESS.md`와 실제 코드는 이번 작업에서 수정하지 않습니다.
