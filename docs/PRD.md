# EXCUSE ME! 제품 요구사항 정의서 (PRD)

**현재 상태(2026-11-05): 랜덤 작품 감상(F08)은 서비스에서 제거되었습니다.** `/random` 화면·메뉴·진입 버튼은 제공하지 않습니다. 이 문서의 F08과 관련 랜덤 흐름은 초기 기획 이력이며 현재 서비스의 요구사항·브라우저 검증 대상에서 제외합니다. 백엔드 호환 API는 이번 제거 범위에 포함하지 않았습니다.

기준 문서: [MVP.md](./MVP.md)

이 문서는 MVP의 기능과 정책을 화면, 사용자 행동, 완료 기준으로 구체화합니다. 기존 F01~F08은 유지하고, 사용자 요청에 따른 설치미술 히어로·이미지 전시 확장은 F09~F13으로 구분합니다. 결정하지 않은 운영 규칙은 **확인 필요**로 표시하며, 기획 확정과 구현 완료를 구분합니다.

## 1. 서비스 소개 및 기획 목적

EXCUSE ME!는 일상 속 황당하고 창의적인 핑계를 예술 작품처럼 등록하고 감상하는 참여형 디지털 박물관입니다.

대화 속에서 잠깐 소비되고 사라지는 재미있는 핑계를 작품으로 모으고, 다른 사람의 경험에 공감을 표현할 수 있게 합니다. 방문객은 짧은 글을 기증하고, 전시된 작품을 감상하며, 마음에 드는 작품을 명작으로 인정합니다.

핵심 메시지는 **Every Excuse Deserves an Exhibition. / 모든 핑계에는 전시될 자격이 있다.**입니다. 기존 텍스트 전시에 사용자가 직접 촬영한 사진전, 이후에는 핑계로 만드는 AI 회화전을 더합니다.

기존 텍스트 핵심 기능을 기본 MVP로 먼저 완성한 뒤 사진전까지 포함한 MVP를 완성합니다. AI 회화전은 비용·구현 난이도를 고려해 사진 포함 MVP 이후의 확장으로 분리합니다. 기존 1~2주 목표는 텍스트 기본 MVP의 초기 가정이며 추가 범위의 일정은 **확인 필요**입니다. React·Tailwind CSS·FastAPI·SQLite 구성은 유지합니다. 이번 작업은 문서 개정만 수행합니다.

## 2. 주요 사용자와 해결하려는 문제

| 항목 | 내용 |
| --- | --- |
| 주요 사용자 | 짧고 재미있는 콘텐츠를 즐기는 LG AX 1기 부트캠프 사람들 |
| 공유하려는 경험 | 지각, 과제, 약속, 운동 등 일상에서 사용했거나 떠올린 재치 있는 핑계 |
| 해결하려는 문제 | 재미있는 핑계가 대화 중에 사라지고, 이를 모아서 감상하고 공감할 공간이 부족함 |
| 사용자의 기대 | 회원가입 없이 작품을 둘러보고, 짧은 글과 간단한 투표로 참여함 |

대표 이용 흐름은 다음과 같습니다.

1. 랜딩페이지에서 서비스 소개를 읽습니다.
2. 상설 전시관에서 작품을 둘러보거나 카테고리를 선택합니다.
3. 작품 감상실에서 전체 내용을 읽고 명작 인정에 참여합니다.
4. 명예의 전당이나 랜덤 감상으로 다음 작품을 발견합니다.
5. 자신의 핑계를 작품으로 기증하고, 필요하면 본인 작품을 수정하거나 삭제합니다.

## 3. 서비스의 핵심 가치와 차별점

- **재미:** 일상의 핑계를 예술 작품처럼 감상합니다.
- **공감:** 다른 사람의 경험에 명작 인정 한 표로 반응합니다.
- **쉬운 참여:** 회원가입 없는 텍스트 기증·투표를 기반으로 사진 기증, 이후 AI 회화 제작으로 참여 방식을 넓힙니다.
- **창의적인 표현:** 평범한 경험을 재치 있는 작품으로 바꿉니다.

일반적인 주제의 게시판보다 '핑계'라는 하나의 소재에 집중합니다. 글쓰기와 읽기를 기증과 감상으로 표현하고, 작품 번호와 명예의 전당을 통해 박물관의 경험을 제공합니다.

| 일반적인 표현 | 서비스 표현 |
| --- | --- |
| 게시글 작성 | 작품 기증 |
| 게시글 목록 | 상설 전시관 |
| 게시글 상세 | 작품 감상실 |
| 좋아요 | 명작 인정 |
| 인기 게시글 | 명예의 전당 |

## 4. 기본 기능 및 확장 요구사항

### F01. 박물관 랜딩페이지

서비스의 주제와 참여 방법을 처음 방문한 사람에게 설명합니다.

- 서비스 이름, 짧은 소개, 핑계 작품 예시를 보여줍니다.
- 정식 회원가입 없이 참여하는 데모라는 안내를 보여줍니다.
- 상설 전시관, 작품 기증, 명예의 전당으로 이동하는 버튼을 제공합니다.
- 랜덤 작품 감상을 시작하는 버튼을 제공합니다.
- 휴대전화와 PC에서 주요 글과 버튼이 잘리지 않아야 합니다.

### F02. 핑계 작품 등록 — 작품 기증

방문객이 작품명(기존 제목), 핑계 내용, 카테고리 한 가지와 작가명을 입력합니다. Phase 2에서는 텍스트 저장을 먼저 완성하고, 이미지 기증은 F10~F12에서 단계적으로 연결합니다. 작가명 필수 여부와 검증 기준은 **확인 필요**입니다.

- 제목과 내용은 필수이며, 비어 있거나 공백만 있는 값은 등록할 수 없습니다.
- 카테고리는 지각, 과제, 약속, 운동, 기타 중 하나여야 합니다.
- 입력이 잘못되면 등록하지 않고 그 이유를 알려줍니다.
- 서비스가 작품 번호, 등록 시각, 기증한 방문객 ID를 자동으로 기록합니다.
- 작품은 현재 방문객 ID에 연결되어 저장됩니다.
- 등록에 성공하면 새 작품의 감상실로 이동합니다. 상설 전시관에서도 해당 작품을 볼 수 있어야 합니다.
- 등록에 실패하면 실패 안내를 제공하며, 사용자가 다시 시도할 수 있어야 합니다.
- 등록한 작품은 새로고침 후에도 유지됩니다.

### F03. 작품 목록 및 상세 조회

상설 전시관은 여러 작품을 발견하는 곳이며, 작품 감상실은 한 작품의 전체 내용을 읽는 곳입니다.

- 목록은 최근에 등록된 작품부터 보여줍니다.
- 목록에는 작품 제목, 카테고리, 명작 인정 수를 표시합니다. F10 적용 후에는 작가명을, F11·F12 적용 후에는 이미지 미리보기와 전시 유형도 표시합니다.
- 작품을 선택하면 해당 감상실로 이동합니다.
- 감상실에는 작품 번호, 제목, 전체 내용, 카테고리, 등록 시각, 명작 인정 수를 표시합니다.
- 감상실에서 목록으로 돌아갈 수 있어야 합니다.
- 전체 작품이 없으면 아직 기증된 작품이 없다는 안내와 작품 기증 버튼을 제공합니다.
- 존재하지 않거나 삭제된 작품의 주소에 접속하면 안내와 전시관으로 돌아가는 버튼을 제공합니다.

### F04. 카테고리별 필터링

상설 전시관에서 관심 있는 상황의 작품만 골라봅니다.

- 선택 항목은 전체, 지각, 과제, 약속, 운동, 기타입니다. '전체'는 조회 항목이며 작품에 저장하는 카테고리가 아닙니다.
- 처음에는 전체 작품을 보여줍니다.
- 카테고리를 고르면 해당 카테고리의 작품만 최근 등록순으로 보여줍니다.
- 현재 선택한 항목을 구분할 수 있어야 합니다.
- 전체를 고르면 모든 작품을 다시 보여줍니다.
- 선택한 카테고리에 작품이 없으면 결과가 없다는 안내를 보여줍니다.

### F05. 본인 작품 수정 및 삭제

기증자가 오타를 고치거나 자신의 작품을 내릴 수 있게 합니다.

- 작품의 방문객 ID와 현재 방문객 ID가 같을 때만 감상실에 수정·삭제 버튼을 보여줍니다.
- 서버도 두 ID를 비교합니다. ID가 일치하지 않는 수정·삭제 요청은 거절합니다.
- 제목, 내용, 카테고리를 수정할 수 있으며 등록과 같은 입력 규칙을 적용합니다.
- 수정 결과는 새로고침 후에도 유지되고, 기존 명작 인정 수는 유지됩니다.
- 삭제 전 확인 안내에서 진행 또는 취소를 선택할 수 있어야 합니다.
- 취소하면 작품을 유지합니다. 확정하면 작품과 연결된 투표를 제거합니다.
- 삭제한 작품은 목록, 상세, 명예의 전당, 랜덤 감상에서 더 이상 나타나지 않습니다.
- 삭제 복구 기능은 제공하지 않습니다.
- ID 비교는 데모 수준의 소유자 구분이며, 실제 사용자 인증을 보장하지 않습니다.

### F06. 작품별 명작 인정 투표 및 취소

방문객이 작품에 공감을 표현하고 이를 취소할 수 있게 합니다.

- 작품 감상실에서 명작 인정 버튼과 현재 투표 수, 본인의 투표 여부를 보여줍니다.
- 아직 투표하지 않은 작품에서 버튼을 누르면 한 표를 추가합니다.
- 이미 투표한 작품에서 같은 버튼을 다시 누르면 해당 방문객의 표를 취소합니다.
- 하나의 방문객 ID는 작품 하나에 한 표만 유지할 수 있습니다.
- 투표하면 수가 1 증가하고 취소하면 1 감소합니다.
- 빠르게 여러 번 눌러도 같은 ID의 표가 중복 저장되거나 투표 수가 음수가 되지 않아야 합니다.
- 새로고침 후에도 투표 수와 해당 방문객의 투표 여부가 유지됩니다.
- 목록과 명예의 전당을 다시 조회하면 변경된 투표 수를 반영합니다.

### F07. 투표 수 기반 명예의 전당 TOP 10

현재 공감을 많이 받은 작품을 순위로 보여줍니다.

- 현재 명작 인정 수가 많은 순서로 최대 10개 작품을 보여줍니다.
- 투표 수가 같으면 등록 시각이 최근인 작품이 먼저입니다.
- 등록 시각도 같으면 작품 번호가 큰 작품이 먼저입니다.
- 작품의 순위와 명작 인정 수를 보여주며, 작품을 선택하면 감상실로 이동합니다.
- 작품이 10개 미만이면 있는 작품만 표시합니다. 작품이 없으면 안내 문구를 표시합니다.
- 투표, 투표 취소, 작품 삭제 후 다시 조회하면 순위를 갱신합니다.
- 운영자 선정이나 수동 등록 없이 투표 수로 순위를 정합니다.

### F08. 랜덤 작품 감상 — 제거됨 (2026-11-05)

방문객이 작품을 직접 고르지 않아도 작품을 발견할 수 있게 합니다.

- 랜딩페이지와 작품 감상실에서 랜덤 감상을 실행할 수 있습니다.
- 삭제되지 않은 전체 작품 중 하나를 무작위로 골라 그 작품의 감상실로 이동합니다.
- 작품이 여러 개일 때 항상 같은 작품으로 고정되지 않아야 합니다. 다만 무작위 선택이므로 같은 작품이 연속으로 나올 수 있습니다.
- 작품이 하나뿐이면 해당 작품을 보여줍니다.
- 작품이 없으면 안내와 작품 기증 버튼을 보여줍니다.
- 개인 취향 분석이나 추천 알고리즘은 포함하지 않습니다.

### F09. 설치미술 히어로 비주얼

- 기존 랜딩페이지 구조·상단 내비게이션·버튼·하단 소개와 대표 카드 섹션·컬러 팔레트를 유지합니다. 변경 대상은 히어로의 비주얼 영역입니다.
- 해당 영역 중앙에 변명을 고민하는 인물을 조각상 또는 설치미술 작품처럼 표현하고, 전시 받침대·오브제를 함께 사용합니다.
- 작품명 **그럴듯한 사유**, 작품 문구 **“조금만 더 생각하면, 완벽한 변명이 나올 것 같았습니다.”**, 전시명 **The Birth of an Excuse**를 사용합니다.
- 핵심 메시지는 이 연출과 서비스 소개의 기준입니다. 기존 메인 카피를 교체할지, 메시지를 어느 위치에 배치할지는 **확인 필요**이며 구조 변경을 임의로 확대하지 않습니다.
- 이 대표 연출은 정적인 랜딩 콘텐츠이며 이용자 작품·DB 등록 결과나 AI 실시간 생성 결과가 아닙니다. 실시간 3D나 애니메이션 구현을 필수로 추가하지 않습니다.
- 에셋 제작 방식·파일 형식·모바일 구도·대체 설명·오브제 세부 구성은 구현 전에 확인합니다.

### F10. 작가명 및 단일 이미지 방식 선택

- 기증 공통 입력은 작품명·핑계 내용·카테고리·작가명입니다. 표시용 작가명과 소유권 확인용 방문객 ID를 분리합니다.
- Phase 2에서는 작가명을 텍스트 작품에 연결합니다. 작가명 필수 여부·길이·중복 이름·수정 허용·기존 데이터의 이름 표시는 **확인 필요**입니다.
- 이미지 기증 단계의 선택지는 **사진 업로드하기 / AI로 작품 만들기**입니다. 한 작품에는 한 방식만 적용합니다.
- AI 도입 전에는 사진 업로드만 실제로 제공하고 AI는 준비 중 또는 선택 불가로 명확히 구분합니다. 미구현 AI를 실행하거나 생성에 성공했다고 안내하지 않습니다.
- 화면과 서버에서 두 방식의 동시 제출 및 선택 방식과 이미지 출처가 다른 제출을 거절합니다. 오류 응답 형식은 **확인 필요**입니다.
- 방식 전환 시 파일·생성 결과·진행 중 요청을 어떻게 처리할지, 이미지 개수와 교체 방식은 **확인 필요**입니다.
- 이미지 도입 뒤 새 텍스트 전용 기증을 계속 허용할지는 **확인 필요**입니다. 기존 텍스트 작품은 삭제하거나 이미지 작품으로 강제 변환하지 않습니다.

### F11. 사진 업로드 및 사진전

- 사용자가 직접 촬영한 사진을 선택하고 미리보기로 확인한 뒤 핑계와 함께 등록합니다.
- 사진전에서는 사진 미리보기와 작품명·작가명·카테고리를 보고, 상세 감상에서는 사진과 전체 핑계 내용을 봅니다.
- 등록 성공은 작품 정보와 사진 연결을 실제로 저장한 뒤 안내하며, 재조회·새로고침·서버 재실행 뒤에도 확인합니다.
- 파일 검증 실패·업로드 실패·작품 저장 실패·사진 조회 실패를 정상 결과와 구분합니다. 이미지 로드 실패를 작품 삭제나 빈 전시관으로 단정하지 않습니다.
- 파일 형식·크기·해상도·개수·압축, 저장 위치·접근 방식, 사진의 개인정보·권리 안내, 메타데이터 제거 여부와 임시 파일·삭제 파일 처리는 **확인 필요**입니다.
- 작품 삭제 시 기존 F05처럼 전시 대상에서 즉시 제외하되, 물리 파일 정리 시점·실패 시 처리는 별도 확정합니다. 공개 시연 범위와 악용 대응도 사진 기능 출시 전에 확인합니다.

### F12. AI 이미지 생성 및 AI 회화전 — 추후 확장

- 사용자가 작성한 핑계를 바탕으로 **수채화, 유화, 점묘화, 연필 드로잉, 콜라주** 중 스타일을 선택해 이미지를 생성합니다. 핑계 문장 자체의 AI 생성은 포함하지 않습니다.
- 생성 요청 → 진행·실패 안내 → 결과 확인 → 사용자 등록 선택 → 작품 저장 → 감상 흐름으로 구분합니다.
- 생성만으로 자동 등록하지 않습니다. 결과를 확인하고 등록한 작품만 AI 회화전과 전체 전시관에 나타납니다.
- 생성 실패·시간 초과·응답 유실·등록 실패를 성공과 구분합니다. 비용 발생 여부를 알 수 없을 때 미과금·무료 재시도라고 단정하지 않습니다.
- 제공사·모델·서버 연동·예산·요청 제한·중복 요청 처리·재생성·취소·콘텐츠 기준·임시 생성물 보관은 **확인 필요**입니다. 실제 비밀키를 클라이언트·Git에 넣지 않습니다.
- 사진 포함 MVP가 완성되고 비용·운영 정책이 결정되기 전에는 구현에 착수하거나 출시 기능으로 표시하지 않습니다.

### F13. 전체 전시관 통합 감상

- 기존 텍스트 작품을 보존하고 전체 전시관에서 활성화된 사진전·AI 회화전 작품을 함께 감상합니다. 사진 단계에는 텍스트·사진, AI 단계에는 두 이미지 유형의 혼합 감상을 확인합니다.
- 카테고리 다섯 가지와 전시 유형을 별개로 취급합니다. 사진전·AI 회화전의 개별 진입 UI·주소·유형 선택·카테고리와의 결합 방식은 **확인 필요**입니다.
- 실제 목록은 기존 최신 등록순을 유지합니다. Phase 1 샘플 인기순을 실제 서비스의 정렬 정책으로 자동 승격하지 않습니다.
- 이미지와 작가명은 해당 작품 번호에 연결합니다. 작가명 일치나 이미지 소지만으로 수정·삭제 권한을 부여하지 않습니다.
- F05~F08의 소유자 확인·투표 유지·TOP 10 동점·삭제 제외·랜덤 규칙을 새 유형에도 동일하게 적용하고 회귀 검증합니다. 아직 미출시인 유형이나 미등록 생성 결과를 포함하지 않습니다.

## 6. 필요한 화면 구성과 화면별 역할

| 구분 | 확정된 정책 |
| --- | --- |
| 작품 형식 | 텍스트 기본 MVP → 사진 포함 MVP → AI 회화전 확장. 기존 텍스트 보존 |

## 8. 공감 투표 및 명예의 전당 운영 규칙

### 투표

- 서비스에서 공감 투표의 이름은 '명작 인정'입니다.
- 현재 투표 수는 해당 작품에 남아 있는 표의 개수입니다.
- 중복 제한의 단위는 실제 사람이 아닌 '방문객 ID와 작품의 조합'입니다.
- 하나의 ID가 서로 다른 작품에 각각 투표할 수 있으며, 작품 하나에는 한 표만 유지합니다.
- 인정 취소는 해당 방문객의 표를 제거하는 행동입니다.
- 작품 수정 시 투표는 유지되고, 작품 삭제 시 연결된 투표는 제거됩니다.
- 다른 브라우저에서 참여한 방문객의 투표 여부는 별도로 유지됩니다.
- 본인 작품에 투표할 수 있는지는 **확인 필요**입니다.

### 명예의 전당

- 최대 10개를 현재 투표 수 내림차순으로 보여줍니다.
- 동점은 등록 시각 내림차순, 그다음 작품 번호 내림차순으로 정합니다. 내림차순은 수가 크거나 시각이 최근인 것을 먼저 보여준다는 뜻입니다.
- 투표·취소·삭제 결과는 다시 조회했을 때 반영되어야 합니다. 실시간 자동 갱신은 확정된 요구사항이 아닙니다.
- MVP에는 별도 운영자 선정, 수동 등록, 기간별 순위, 최소 득표 조건이 정해져 있지 않습니다. 별도 기간이나 최소 득표 조건을 둘지는 **확인 필요**이며, 이 문서에서 새 제한을 추가하지 않습니다.

## 9. 데모 방문객 ID 방식과 보안상 한계

### 동작 방식

- 최초 방문 시 임의의 ID를 만들고 브라우저에 저장합니다.
- 저장 정보가 유지되는 동안 새로고침과 재방문에도 같은 ID를 사용합니다.
- ID는 본인 작품과 본인의 투표 여부를 구분하는 기준입니다.
- 브라우저나 기기가 다르면 다른 방문객으로 취급합니다. 같은 브라우저를 함께 사용하면 같은 방문객으로 취급될 수 있습니다.
- 브라우저 저장 정보 삭제나 시크릿 창 이용 시 기존 ID를 계속 사용할 수 없습니다.
- 기존 작품이 남아 있더라도 이전 ID를 잃으면 본인 작품의 수정·삭제 권한을 잃을 수 있습니다. 첫 버전에 ID 복구 기능은 없습니다.

### 한계와 안내

**데모 방문객 ID는 실제 사용자 인증을 대신할 수 없습니다.** 사용자가 저장된 ID를 변경하거나 복사할 수 있기 때문입니다.

- 다른 방문객의 ID를 흉내 내는 상황을 막는 실제 인증 수단이 아닙니다.
- 여러 ID를 이용한 투표를 막지 못하므로 실제 사람 한 명당 한 표를 보장하지 않습니다.
- 서버의 ID 비교는 반드시 구현하지만, ID를 보내는 사람이 실제 기증자인지 증명하지는 못합니다.
- 실제 인증이 아니라는 점과 저장 정보 삭제 시 본인 작품 관리 권한을 잃을 수 있다는 점을 사용자가 볼 수 있게 안내해야 합니다.
- 공개 서비스로 확장할 때는 정식 인증과 권한 확인이 필요하지만, 이번 MVP의 구현 범위에는 포함하지 않습니다.

ID를 브라우저 어디에 저장할지, 어떤 형식으로 만들지, 서버에 어떤 방식으로 전달할지는 **확인 필요**입니다. 구체적인 기술 선택은 후속 SPEC에서 다룹니다.

## 10. MVP에서 제외할 기능과 미정 사항

### 제외 및 후순위 범위

- 댓글과 답글
- AI 이미지 생성·AI 회화전은 사진 포함 MVP 이후의 확장입니다. 사진 업로드·사진전은 이번 개정의 MVP에 포함합니다.
- AI 핑계 문장 생성은 계속 제외하며, 핑계 기반 AI 이미지 생성(F12)과 구분합니다.
- 정식 회원가입과 로그인
- 검색, 알림, 팔로우, 개인별 추천
- 별도의 관리자 화면
- 복잡한 목록 정렬 옵션과 무한 스크롤: MVP에서 후순위로 둔 항목이며 첫 구현의 필수 범위에 넣지 않습니다.

## 11. 기능별 완료 판단 기준

아래 기준은 기능을 만들었다고 판단하기 위한 실제 확인 항목입니다.

### F01 완료 기준

- 서비스 이름·소개·작품 예시·회원가입 없는 데모 안내를 확인할 수 있습니다.
- 전시관, 기증, 명예의 전당, 랜덤 감상 버튼이 각각 해당 기능으로 연결됩니다.
- 휴대전화와 PC에서 주요 글과 버튼이 잘리지 않습니다.

### F02 완료 기준

- 올바른 제목·내용·카테고리로 등록하면 현재 방문객에 연결된 작품이 저장되고 감상실로 이동합니다.
- 빈 값·공백뿐인 제목이나 내용·허용하지 않은 카테고리로는 등록되지 않으며 이유가 보입니다.
- 작품 번호와 등록 시각이 자동 기록되고, 작품이 목록에 나타나며 새로고침 후에도 유지됩니다.
- 등록 실패를 성공으로 안내하지 않고 다시 시도할 수 있습니다.

### F03 완료 기준

- 목록이 최근 등록순이며 제목·카테고리·투표 수를 표시합니다.
- 선택한 작품의 감상실에서 작품 번호·제목·전체 내용·카테고리·등록 시각·투표 수가 보이고 목록으로 돌아갈 수 있습니다.
- 작품이 없을 때 안내와 기증 버튼이 보입니다.
- 없는 작품이나 삭제한 작품의 주소에서는 안내와 전시관 복귀 버튼이 보입니다.

### F04 완료 기준

- 최초에는 전체 작품이 보입니다.
- 다섯 카테고리를 각각 선택하면 해당 작품만 최근 등록순으로 표시됩니다.
- 선택 상태를 구분할 수 있고, 전체를 선택하면 모든 작품이 다시 보입니다.
- 해당 카테고리에 작품이 없을 때 결과 없음 안내가 보입니다.

### F05 완료 기준

- 본인 작품에서만 수정·삭제 버튼이 보이고, 서버도 ID가 다른 요청을 거절합니다.
- 제목·내용·카테고리 수정 시 등록과 같은 검증을 적용하며, 저장 결과와 기존 투표 수가 새로고침 후에도 유지됩니다.
- 삭제 취소 시 작품이 유지됩니다.
- 삭제 확정 시 작품과 연결 투표가 제거됩니다. 목록·상세·명예의 전당·랜덤 감상에서 제외되고 새로고침해도 되살아나지 않습니다.

### F06 완료 기준

- 명작 인정으로 한 표가 늘어나고, 같은 버튼을 다시 눌러 취소하면 한 표가 줄어듭니다.
- 빠르게 반복해서 눌러도 같은 ID와 작품에 표가 중복 저장되지 않고 투표 수가 음수가 되지 않습니다.
- 투표 수와 본인 투표 여부가 새로고침 후에도 유지됩니다.
- 투표·취소 후 목록과 명예의 전당을 다시 조회하면 변경된 수가 보입니다.

### F07 완료 기준

- 최대 10개 작품이 투표 수, 등록 시각, 작품 번호 순의 정해진 기준으로 정렬됩니다.
- 순위와 투표 수를 확인할 수 있고 작품 감상실로 이동할 수 있습니다.
- 10개 미만이면 있는 작품만 표시하며, 0개일 때 안내가 보입니다.
- 투표·취소·삭제 후 다시 조회하면 변경된 순위가 보입니다.

### F08 완료 기준

- 랜딩페이지와 감상실에서 실행하면 삭제되지 않은 전체 작품 중 하나의 감상실로 이동합니다.
- 작품이 여러 개일 때 선택이 하나로 고정되지 않습니다. 같은 작품이 연속 선택됐다는 이유만으로 오류로 판단하지 않습니다.
- 작품이 하나면 그 작품이 보이고, 작품이 없으면 안내와 기증 버튼이 보입니다.

### F09~F13 완료 기준

| 기능 | 완료 판정 |
| --- | --- |
| F09 | 대표 작품명·문구·전시명이 맞고 고민하는 인물·받침대·오브제 연출이 보임. 기존 컬러·구조·하단·이동·모바일·health 유지 |
| F10 | 작가명 표시와 방문객 ID 권한을 분리. 이미지 방식은 하나이며 동시·불일치 입력 거절. 사진 단계의 AI는 미출시 안내 |
| F11 | 검증된 사진을 미리보기 후 등록하고 새로고침·서버 재실행·다른 방문객 조회에서 확인. 관련 파일·저장 실패와 삭제 제외 검증 |
| F12 | 다섯 스타일의 생성·결과 확인·선택 등록·실패 안내와 확정된 비용·제한 정책 검증. 생성만으로 등록되지 않음. 사진 포함 MVP 완료 조건에서 제외 |
| F13 | 단계별 혼합 목록·미리보기·상세·카테고리·최신순과 기존 소유자·투표·순위·랜덤·삭제 규칙이 유지됨 |

F10·F13은 단계별 적용 범위를 따로 판정합니다. 사진 단계에서 AI 관련 부분까지 완료했다고 기록하지 않습니다. 미정 정책에 직접 의존하는 시험은 보류로 남깁니다.

### 공통 완료 기준

- 브라우저 A에서 기증한 작품을 브라우저 B에서도 감상할 수 있습니다.
- 다른 ID를 사용하는 B는 일반적인 이용 흐름에서 A의 작품을 수정하거나 삭제할 수 없으며, 두 방문객의 투표 여부는 별도로 유지됩니다.
- 작품 등록·수정·삭제, 투표·취소 결과가 새로고침 후에도 유지됩니다.
- 불러오는 중이라는 표시와 조회·저장 실패 안내가 있으며, 실패한 저장을 성공으로 표시하지 않습니다.
- 휴대전화와 PC에서 기증·감상·투표의 핵심 흐름을 사용할 수 있습니다.
- 사용자가 데모 ID의 인증 한계와 저장 정보 삭제 시 본인 작품 관리 권한을 잃을 수 있다는 안내를 볼 수 있습니다.
- 기본 MVP는 F01~F08·F09·F10 작가명 부분, 사진 포함 MVP는 여기에 F10의 이미지 선택·F11·F13 텍스트/사진 부분을 충족해야 합니다. F12와 F13 AI 부분은 별도 확장 완료 기준입니다. 확인 필요 항목은 확정 정책이나 완료 기능으로 취급하지 않습니다.

## 12. 범위 변경·현재 구현과의 관계

이 개정은 기존의 “텍스트만 제공 / 이미지 제외”를 단계적 사진 MVP·후속 AI 확장으로 바꾸고, 작가명과 단일 이미지 방식을 추가합니다. F01~F08의 카테고리·ID·투표·순위·삭제·랜덤 정책은 유지합니다. AI 이미지 생성 추가가 AI 핑계 문장 생성 허용을 뜻하지 않습니다.

기존 Phase 1 구조와 메인 배경 `#F9FAFB`, 텍스트 `#24201F`, 버건디 `#A32632`, 카드·버튼·테두리의 기존 세부 색상을 유지합니다. 설치미술 연출은 Phase 1 검증·Git 저장 다음의 별도 작업이며 이번 문서 작업에서 화면을 바꾸지 않습니다.

실제 코드에는 8개 고정 샘플과 가상 작가명·인정 수, 샘플 카테고리·정렬, 미구현 안내가 있습니다. 실제 기증·작가명 저장·사진·AI·투표 기능이 구현된 것은 아닙니다. Phase 0의 완료 기록은 유지하며, Phase 1의 필수 화면 검증과 Git 저장은 먼저 마무리합니다. PROGRESS는 이전 시점 기록으로 이번 수정 대상이 아닙니다.
