# EXCUSE ME! 기능 동작 설명서 (SPEC)

**현재 상태(2026-11-05): 랜덤 작품 감상(F08)은 서비스에서 제거되었습니다.** `/random` 화면·메뉴·진입 버튼은 제공하지 않습니다. 이 문서의 F08과 관련 랜덤 흐름은 초기 기획 이력이며 현재 서비스의 요구사항·브라우저 검증 대상에서 제외합니다. 백엔드 호환 API는 이번 제거 범위에 포함하지 않았습니다.

기준 문서: [MVP.md](./MVP.md), [PRD.md](./PRD.md)

이 문서는 PRD의 F01~F08과 추가 기능 F09~F13을 사용자 행동, 정상 결과, 예외 처리, 사용 권한, 테스트 방법으로 설명합니다. 기존 정책을 유지하되 이번 개정에서 사진 MVP와 후속 AI 확장을 반영합니다. 미정 사항은 **확인 필요**입니다. 아래 테스트 시나리오는 구현 후 수행할 방법이며 이번 문서 작업에서 실행한 결과가 아닙니다.

## 1. 공통 용어와 동작 원칙

### 작품과 화면

- 작품명은 기존 문서의 '제목'과 같은 항목입니다. 작품명과 제목을 따로 저장하지 않습니다.
- 작품 등록은 '작품 기증', 목록은 '상설 전시관', 상세는 '작품 감상실', 공감 투표는 '명작 인정'입니다.
- 작품의 공통 정보는 작품명(기존 제목), 핑계 내용, 카테고리와 표시용 작가명(F10)입니다. 작가명 필수 여부·검증·기존 데이터 표시는 **확인 필요**입니다.
- 기본 MVP의 DB 단계는 텍스트를 먼저 저장합니다. 사진 MVP에서 사진 연결(F11)을 추가하고, 이후 AI 확장에서 생성 이미지(F12)를 추가합니다. 기존 텍스트 작품은 보존합니다.
- 상황 카테고리와 전시 유형은 별개입니다. 전체 전시관의 혼합 조회는 F13을 따릅니다.
- 이미지 기증은 사진 업로드 또는 AI 생성 중 하나만 적용하며, 미출시 AI는 실행 불가로 구분합니다. 두 방식 동시 제출을 허용하지 않습니다.
- 작가명은 표시 정보이고 방문객 ID가 소유자·투표 구분 기준입니다. 샘플의 작가명·이미지·인정 수는 실제 저장 결과가 아닙니다.
- 등록 시 작품 번호, 등록 시각, 기증한 방문객 ID를 자동 기록합니다.
- 카테고리는 **지각, 과제, 약속, 운동, 기타**입니다. '전체'는 목록을 보는 선택 항목이며 등록 카테고리가 아닙니다.
- 조회·필터·랜덤 감상만으로 작품이나 투표를 추가·수정·삭제하지 않습니다.
- 조회 중임을 표시하고, 서버 또는 데이터베이스(DB) 요청이 실패하면 이해할 수 있는 안내를 제공합니다.
- 실패한 저장을 성공했다고 표시하지 않습니다. 구체적인 안내 문구와 표시 위치는 **확인 필요**입니다.
- 휴대전화와 PC에서 기증, 감상, 투표의 핵심 흐름을 사용할 수 있어야 합니다.

### 방문객 ID와 권한

- 회원가입 없이 모든 데모 방문객이 작품을 조회하고 기증할 수 있습니다.
- 최초 방문 시 임의의 방문객 ID를 만들어 브라우저에 저장합니다. 저장 정보가 유지되면 새로고침·재방문에도 같은 ID를 사용합니다.
- 본인 작품은 작품에 기록된 방문객 ID와 현재 ID가 같은 작품입니다.
- 수정·삭제 버튼은 본인 작품에서만 표시하며, 서버도 ID를 비교해 불일치 요청을 거절합니다.
- 투표 여부는 방문객 ID별로 구분합니다. 다른 방문객의 표를 자신의 취소 동작으로 제거하지 않습니다.
- **데모 방문객 ID는 실제 보안 인증이 아닙니다.** ID를 변경하거나 복사해 다른 방문객을 흉내 낼 수 있으며, 여러 ID를 이용한 투표도 막지 못합니다. 실제 사람 한 명당 한 표를 보장하지 않습니다.
- 브라우저·기기가 다르면 별도 방문객으로 취급합니다. 같은 브라우저를 함께 쓰면 같은 방문객으로 취급될 수 있습니다.
- 브라우저 저장 정보 삭제나 시크릿 창 이용 시 이전 ID를 계속 사용할 수 없습니다. 작품은 남더라도 이전 작품의 수정·삭제 권한을 잃을 수 있으며 ID 복구 기능은 없습니다.
- 실제 인증이 아니라는 점과 저장 정보 삭제 시 본인 작품 관리 권한을 잃을 수 있다는 점을 사용자에게 안내합니다.
- ID의 형식, 저장 위치, 서버 전달 방식은 **확인 필요**입니다. ID가 없거나 저장에 실패했을 때의 세부 처리도 **확인 필요**이며, 이를 다른 사람의 작품을 수정·삭제할 수 있는 예외로 해석하지 않습니다.

### 입력 길이와 공백

- 제목과 내용이 비어 있거나 공백뿐이면 등록·수정을 거절하고 이유를 표시합니다.
- 제목과 내용의 최대 글자 수는 **확인 필요**입니다. 이 문서에서 특정 숫자를 정하지 않습니다.
- 글자 수를 세는 기준과 앞뒤 공백을 자동으로 정리하는 방식도 **확인 필요**입니다. 공백뿐인 입력 거절은 이미 확정된 규칙이므로 별도로 적용합니다.
- 따라서 '글자 수 제한 초과'의 허용·거절 판정은 상한과 계산 방식이 정해지기 전에는 확정할 수 없습니다. 상세한 조건부 테스트는 3절에 정리합니다.

## 2. 기능별 동작과 테스트

F01~F08의 원래 기능 번호와 정책은 유지합니다. 아래 저장 테스트는 F10 도입 후에는 확정된 작가명 정책에 맞춘 공통 입력도 준비합니다. Phase 1 샘플 화면에서 버튼 안내가 보이는 것은 실제 등록·조회·투표 성공을 뜻하지 않으며, 전체 F01~F08 완료로 판정하지 않습니다.

### F01. 박물관 랜딩페이지

#### 1) 사용자 입력과 버튼

- 첫 화면을 열어 서비스 이름, 소개, 핑계 작품 예시, 회원가입 없는 데모 안내를 읽습니다.
- 상설 전시관, 작품 기증, 명예의 전당 이동 버튼을 누릅니다.
- 랜덤 작품 감상 버튼을 누릅니다.

#### 2) 정상 처리와 저장·표시 결과

- 소개와 예시가 표시되고, 이동 버튼을 누르면 해당 화면이 열립니다.
- 랜덤 버튼은 F08을 실행합니다.
- 첫 방문의 공통 ID 생성·저장 외에, 랜딩페이지를 보거나 이동하는 것만으로 작품·투표를 저장하지 않습니다.

#### 3) 잘못된 입력과 처리 실패

- 이 기능에는 작품을 입력하는 칸이 없습니다.
- 연결된 화면의 조회가 실패하면 해당 기능의 실패 안내를 적용합니다. 랜덤 조회 실패는 F08을 따릅니다.
- 작품이 없다는 이유로 작품 기증이나 전시관 이동을 막지 않습니다. 이동 후의 빈 화면 처리는 F03·F07·F08을 따릅니다.
- 현재 Phase 1 예시는 고정 샘플이며 설치미술 히어로(F09)도 랜딩 연출용 콘텐츠입니다. 실제 DB 작품을 조회하거나 실시간 AI 생성 요청을 실행하지 않습니다. 이후 DB 연동 예시로 바꿀지는 **확인 필요**입니다.

#### 4) 사용·조회·변경 권한

- 모든 데모 방문객이 소개를 읽고 각 기능으로 이동할 수 있습니다.
- 이 화면 자체에는 작품·투표 수정·삭제 기능이 없습니다.

#### 5) 테스트 방법

| 번호 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| F01-T01 | 첫 화면을 엽니다. | 이름·소개·작품 예시·데모 안내가 보입니다. |
| F01-T02 | 전시관·기증·명예의 전당 버튼을 각각 누릅니다. | 각 화면으로 이동합니다. |
| F01-T03 | 랜덤 감상 버튼을 누릅니다. | F08의 작품 수별 결과로 연결됩니다. |
| F01-T04 | 휴대전화와 PC 크기에서 화면을 봅니다. | 주요 글과 버튼이 잘리지 않고 사용할 수 있습니다. |

### F02. 핑계 작품 등록 — 작품 기증

#### 1) 사용자 입력과 버튼

- 작품명과 핑계 내용을 작성하고 다섯 카테고리 중 하나와 작가명을 입력합니다. 작가명 검증·표시는 F10을 따르며 이미지 방식은 사진 단계부터 연결합니다.
- 작품 기증 버튼을 누릅니다.
- 입력 오류나 등록 실패 안내를 확인한 뒤 다시 시도할 수 있습니다.

#### 2) 정상 처리와 저장·표시 결과

- 필수 입력과 카테고리가 올바르면 제목·내용·카테고리를 현재 방문객 ID에 연결해 저장합니다.
- 작품 번호와 등록 시각을 자동 기록합니다.
- 성공한 작품의 감상실로 이동하고, 전시관에서도 작품이 보입니다.
- 새로고침 후에도 작품이 남아 있습니다. 다른 방문객도 해당 작품을 감상할 수 있습니다.

#### 3) 잘못된 입력과 처리 실패

- 제목 또는 내용이 비어 있거나 공백뿐이면 등록하지 않고 어느 입력이 잘못됐는지 안내합니다.
- 카테고리를 선택하지 않았거나 정해진 다섯 값이 아니면 등록하지 않고 이유를 안내합니다.
- 글자 수 제한과 초과 처리의 세부 동작은 **확인 필요**입니다. 3절의 조건부 기준을 따릅니다.
- 서버·DB 저장에 실패한 것이 확인되면 실패 안내를 표시합니다. 성공한 작품인 것처럼 감상실로 이동시키지 않습니다.
- 응답을 받지 못한 경우에는 실제 저장 여부를 단정할 수 없습니다. 3절의 실패 구분을 따릅니다.
- 실패 후 작성 중인 입력 내용 유지 방식은 **확인 필요**입니다.

#### 4) 사용·조회·변경 권한

- 모든 데모 방문객이 자신의 ID로 작품을 기증할 수 있습니다.
- 기증한 작품은 다른 방문객도 조회할 수 있습니다.
- 이후 수정·삭제는 F05의 본인 작품 규칙을 따릅니다.

#### 5) 테스트 방법

| 번호 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| F02-T01 | 올바른 제목·내용과 '지각'을 입력해 기증합니다. | 현재 ID에 연결된 작품이 저장되고 번호·등록 시각이 있는 감상실로 이동합니다. 목록과 새로고침 후에도 확인됩니다. |
| F02-T02 | 제목과 내용을 각각 빈 값, 공백뿐인 값으로 바꿔 기증합니다. | 각 경우 등록되지 않고 이유가 표시됩니다. |
| F02-T03 | 카테고리 미선택 또는 허용하지 않은 값으로 등록을 요청합니다. | 등록되지 않고 이유가 표시됩니다. 서버 요청을 직접 보내는 확인은 구현 후 개발 도구로 진행합니다. |
| F02-T04 | 테스트 환경에서 서버를 끄거나 DB 저장 오류를 발생시킨 뒤 기증합니다. | 실패·결과 확인 불가 상황을 성공으로 표시하지 않습니다. 실제 저장 여부는 3절 기준으로 확인합니다. |
| F02-T05 | 글자 수 상한이 확정된 뒤 3절의 경계값 테스트를 수행합니다. | 현재는 정책 미정으로 판정 보류합니다. 확정 전 임의의 길이 제한을 완료 기준으로 쓰지 않습니다. |

### F03. 작품 목록 및 상세 조회

#### 1) 사용자 입력과 버튼

- 상설 전시관을 엽니다.
- 작품을 선택하거나 작품 상세 주소로 접속합니다.
- 감상실에서 목록으로 돌아가는 버튼을 누릅니다.

#### 2) 정상 처리와 저장·표시 결과

- 목록은 최근 등록순이며 작품 제목·카테고리·명작 인정 수를 표시합니다.
- 감상실은 작품 번호·제목·전체 내용·카테고리·등록 시각·명작 인정 수를 표시합니다.
- 조회만으로 작품과 투표 데이터를 변경하지 않습니다.
- 본인 작품 버튼과 투표 상태는 각각 F05·F06의 기준으로 표시합니다.

#### 3) 잘못된 입력과 처리 실패

- 작품이 하나도 없으면 아직 기증된 작품이 없다는 안내와 작품 기증 버튼을 표시합니다.
- 삭제되었거나 존재하지 않는 작품에 접속하면 해당 작품을 볼 수 없다는 안내와 전시관 복귀 버튼을 표시합니다.
- 서버·DB 조회가 실패하면 실패 안내를 표시합니다. 작품이 0개라고 확인된 상황이나 작품이 없다고 확인된 상황과 구분합니다.
- 목록에서 감상실로 이동하는 사이 작품이 삭제된 경우에도 없는 작품 안내를 적용합니다.
- 일반 목록에서 등록 시각이 같은 작품의 순서, 표시 개수·페이지 나누기, 목록 복귀 시 필터·스크롤 유지 여부는 **확인 필요**입니다.

#### 4) 사용·조회·변경 권한

- 모든 데모 방문객이 본인과 다른 방문객의 작품을 조회할 수 있습니다.
- 다른 사람의 작품을 조회할 수 있다는 것이 수정·삭제 권한을 의미하지는 않습니다.
- 이 기능은 작품이나 투표를 수정·삭제하지 않습니다.

#### 5) 테스트 방법

| 번호 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| F03-T01 | 등록 시각이 서로 다른 작품 여러 개를 준비하고 목록을 엽니다. | 최근 등록순이며 목록 필수 정보가 보입니다. |

### F05. 본인 작품 수정 및 삭제

#### 2) 정상 처리와 저장·표시 결과

- 삭제를 취소하면 작품을 유지합니다.
- 삭제를 확정하고 처리가 성공하면 작품과 연결된 투표를 제거합니다. 목록·상세·명예의 전당·랜덤 감상에서 제외되며 복구 기능은 없습니다.
- 수정 성공 후의 화면 이동 방식, 삭제 성공 직후 이동할 화면은 **확인 필요**입니다. 삭제된 작품을 계속 감상 가능한 상태로 표시해서는 안 됩니다.

#### 3) 잘못된 입력과 처리 실패

- 빈 제목·내용, 공백뿐인 제목·내용, 잘못된 카테고리는 수정에 저장하지 않고 이유를 안내합니다. 기존의 정상 작품을 해당 잘못된 입력으로 바꾸지 않습니다.
- 글자 수 제한 초과 판정은 **확인 필요**이며 등록과 같은 기준을 적용해야 합니다.
- 다른 방문객의 작품에는 수정·삭제 버튼을 표시하지 않습니다. 다른 ID로 서버에 직접 수정·삭제 요청을 보내도 거절하며 원래 작품과 투표를 변경하지 않습니다.
- 이미 삭제되었거나 존재하지 않는 작품이면 F03의 작품 없음 안내와 전시관 복귀를 적용합니다. 수정·삭제 성공으로 표시하지 않습니다.
- 서버·DB 요청에 실패하면 실패 안내를 제공합니다. 응답만 받지 못한 경우는 실제 변경 여부를 단정하지 않고 3절을 따릅니다.
- 수정 실패 후 입력 유지, 수정 화면 표시 방식, 삭제 확인 안내 표시 방식은 **확인 필요**입니다.

#### 4) 사용·조회·변경 권한

- 작품 조회는 모든 방문객에게 열려 있습니다.
- 수정·삭제는 작품에 저장된 ID와 현재 ID가 같을 때만 허용합니다.
- ID를 복사하거나 조작한 사람까지 구분하는 실제 인증 기능은 없으므로 이 제한은 데모 수준입니다.

### F06. 작품별 명작 인정 투표 및 취소

#### 1) 사용자 입력과 버튼

- 감상실에서 현재 투표 수와 본인의 인정 여부를 확인합니다.
- 아직 인정하지 않은 작품에서 명작 인정 버튼을 누릅니다.
- 이미 인정한 작품에서 같은 버튼을 다시 눌러 취소합니다.

#### 2) 정상 처리와 저장·표시 결과

- 인정하면 현재 방문객 ID와 작품에 연결된 한 표를 저장하고 수를 1 늘립니다. 버튼에 본인의 인정 상태를 구분해 표시합니다.
- 취소하면 해당 방문객의 표를 제거하고 수를 1 줄입니다. 다른 방문객의 표는 유지합니다.
- 같은 ID와 작품에는 최대 한 표만 남아야 합니다.
- 투표 수는 작품에 남아 있는 표의 개수이며 음수가 될 수 없습니다.
- 새로고침 후에도 투표 수와 본인 상태를 유지합니다. 목록·명예의 전당을 다시 조회하면 결과를 반영합니다.

#### 3) 잘못된 입력과 처리 실패

- 같은 방문객의 동일한 인정 요청이 중복 전달되어도 표를 추가로 쌓지 않습니다. 중복 요청의 구체적인 응답 문구·형식은 **확인 필요**입니다.
- 이미 인정한 상태에서 버튼을 다시 누르는 정상 행동은 '취소'입니다. 중복된 인정 요청을 무조건 취소로 바꾸는 것과 구분합니다.
- 빠른 연속 클릭에서도 중복 표와 음수 투표 수가 발생하면 안 됩니다. 연속 클릭 처리 순서나 버튼 잠금 방식은 **확인 필요**이며, 클릭 횟수만으로 최종 상태를 임의로 확정하지 않습니다.
- 취소 요청이 반복되어도 다른 방문객의 표를 지우거나 수가 음수가 되어서는 안 됩니다. 이미 본인 표가 없는 상태의 취소 요청에 어떤 응답을 할지는 **확인 필요**입니다.
- 작품이 삭제되었거나 존재하지 않으면 없는 작품 안내를 적용하며 유효한 투표 대상으로 처리하지 않습니다.
- 서버·DB 요청이 실패하면 인정·취소 성공으로 안내하지 않습니다. 응답을 받지 못한 경우 실제 표가 남았는지는 3절에 따라 확인합니다.
- 본인 작품에 투표할 수 있는지는 **확인 필요**입니다. 해당 정책이 확정되기 전에는 본인 작품 투표를 성공·실패 테스트의 전제로 삼지 않습니다.

#### 4) 사용·조회·변경 권한

- 모든 데모 방문객이 작품의 투표 수를 볼 수 있습니다.
- 방문객은 자신의 ID로 인정하거나 자신의 표를 취소합니다. 본인 작품에 대한 허용 여부는 미정입니다.
- 다른 방문객의 투표 여부와 자신의 투표 여부는 별도로 유지합니다.
- ID 변경·복사에 의한 우회는 막지 못하며 실제 사람당 한 표를 보장하지 않습니다.

### F07. 투표 수 기반 명예의 전당 TOP 10

- 순위 조회는 작품이나 표를 추가·수정·삭제하지 않습니다. 운영자 선정이나 수동 등록도 없습니다.

#### 4) 사용·조회·변경 권한

### F08. 랜덤 작품 감상 — 제거됨 (2026-11-05)

#### 1) 사용자 입력과 버튼

- 랜딩페이지 또는 감상실에서 랜덤 감상 버튼을 누릅니다.

#### 2) 정상 처리와 저장·표시 결과

- 삭제되지 않은 전체 작품 중 하나를 무작위로 골라 해당 감상실로 이동합니다.
- 작품이 하나뿐이면 그 작품을 보여줍니다.
- 카테고리 필터나 개인 취향에 따른 추천 기능을 추가하지 않습니다.
- 무작위 선택만으로 작품·투표를 저장하거나 변경하지 않습니다.
- 같은 작품이 연속으로 선택될 수 있습니다.

#### 3) 잘못된 입력과 처리 실패

- 작품이 없으면 안내와 작품 기증 버튼을 표시합니다.

- 개인 취향 분석과 추천 알고리즘은 구현하지 않습니다.

#### 4) 사용·조회·변경 권한

- 모든 데모 방문객이 전체 작품을 대상으로 랜덤 감상을 사용할 수 있습니다.

| F12-T05 | 승인된 예산·제한 경계와 클라이언트·Git의 비밀값 노출 여부를 확인합니다. | 정책에 맞는 제한과 안내, 실제 키 노출 없음. 미정 정책은 보류합니다. |

### F13. 전체 전시관 통합 감상

#### 1) 입력·정상 결과

전체 전시관에서 기존 텍스트와 활성화된 사진·AI 작품을 함께 조회하고 상세 감상으로 연결합니다. 사진 MVP에는 텍스트·사진만, AI 확장 후에는 두 이미지 유형 모두 포함합니다. 작품 번호·작가명·내용·카테고리·전시 유형·이미지를 일관되게 연결합니다.

기존 카테고리 필터와 실제 최신 등록순은 유지합니다. 사진전·AI 회화전의 유형별 진입 UI·주소 및 카테고리와 결합하는 방식은 **확인 필요**입니다. 현재 샘플 인기순은 실제 서비스 정렬 정책이 아닙니다. 기존 텍스트의 이미지 없음과 이미지 작품의 로드 실패를 구분합니다.

#### 2) 권한·확장 연계

기존 텍스트를 삭제하거나 이미지로 강제 변환하지 않습니다. 등록되지 않은 미리보기·생성 결과를 포함하지 않습니다. 활성화된 새 유형에도 기존 F05~F08의 ID 비교·투표 보존·순위 동점·전체 작품 랜덤·삭제 제외를 적용하고 회귀 테스트합니다. 이미지 교체 시 투표·파일 처리 세부 기준은 확인 전 구현하지 않습니다.

## 3. 주요 예외 상황의 상세 기준

### E01. 작품명 또는 핑계 내용이 비어 있음

- 적용 기능: F02 등록, F05 수정.
- 제목 빈 값, 제목 공백뿐인 값, 내용 빈 값, 내용 공백뿐인 값을 각각 확인합니다.
- 등록은 작품을 만들지 않고, 수정은 잘못된 입력으로 기존 작품을 바꾸지 않습니다.
- 어떤 입력을 채워야 하는지 이해할 수 있는 이유를 표시합니다.
- 공백만 있는지 판단하는 것과 앞뒤 공백을 자동으로 지우는 정책은 다릅니다. 자동 정리 방식은 미정입니다.

### E02. 입력 글자 수 제한 초과

- 적용 기능: F02 등록, F05 수정.
- 현재 제목·내용의 상한과 글자 수 계산 방식은 **확인 필요**입니다. 지금은 특정 길이의 입력을 초과 오류로 확정하지 않습니다.
- 상한이 확정되면 제목 상한을 L제목, 내용 상한을 L내용이라고 두고 각 항목을 상한보다 한 글자 적게, 같은 길이, 한 글자 많게 입력해 확인합니다. 다른 입력은 올바른 값으로 둡니다.
- 길이 이외의 입력 조건도 올바른 경우, 최대 길이까지 허용하고 초과 입력은 저장되지 않는지 확인하는 테스트를 정책 확정 후 적용합니다.
- 입력 중 초과를 막을지, 기증·저장 시 오류를 보일지, 문구를 어떻게 표시할지는 **확인 필요**입니다. 자동으로 내용을 잘라 저장한다고 가정하지 않습니다.
- 한글·줄바꿈·이모지의 글자 수 계산도 확정된 방식으로 동일하게 확인해야 합니다. 확정 전에는 경계값 테스트를 '통과'로 기록하지 않습니다.

### E03. 등록된 작품이 하나도 없음

| 위치 | 사용자에게 표시할 결과 |
| --- | --- |
| 상설 전시관 | 아직 기증된 작품이 없다는 안내와 작품 기증 버튼 |
| 카테고리 필터 결과 | 해당 결과가 없다는 안내 |
| 명예의 전당 | 작품이 없다는 안내 |
| 랜덤 감상 | 작품이 없다는 안내와 작품 기증 버튼 |

조회가 성공해서 0개임을 확인한 경우에 적용합니다. 요청 실패를 0개로 바꿔 표시하지 않습니다.

### E04. 다른 방문객의 작품 수정·삭제 시도

- A의 작품을 다른 ID의 B가 조회할 수는 있지만 수정·삭제 버튼은 보이지 않습니다.
- B가 화면을 우회해 서버에 수정·삭제 요청을 보내도 서버는 작품 ID와 요청에 쓰인 방문객 ID를 기준으로 소유자를 확인하고 거절합니다.
- 거절된 요청으로 작품과 연결 투표가 변경되면 안 됩니다.
- 권한 없음 안내의 정확한 문구와 응답 형식은 **확인 필요**입니다.
- 이 확인은 B가 자신의 다른 ID를 사용한 경우의 제한입니다. A의 ID 자체를 복사한 B를 구분하는 실제 인증은 제공하지 않습니다.

### E05. 동일 방문객의 중복 투표와 취소

- 같은 ID가 같은 작품에 보내는 중복된 인정 요청은 표를 여러 개 만들지 않아야 합니다.
- 이미 인정한 화면에서 다시 누르는 것은 정상적인 취소이며 해당 ID의 표 한 개를 제거합니다.
- 다른 ID의 표는 취소 대상이 아니며 남은 투표 수는 음수가 될 수 없습니다.
- 반복 요청 후 서버의 실제 표 수, 화면의 수, 새로고침 후 본인 상태를 비교합니다.
- 중복 인정과 반복 취소의 구체적인 응답, 빠른 클릭의 처리 순서는 **확인 필요**입니다. 새 API나 자동 반전 규칙을 이 문서에서 정하지 않습니다.

### E06. 삭제되었거나 존재하지 않는 작품

- 상세 주소 직접 접속, 오래된 목록·순위에서 선택, 수정·삭제·투표 시점에 작품이 사라진 경우를 각각 확인합니다.
- 작품 없음 안내와 전시관 복귀 버튼을 제공합니다.
- 없는 작품을 정상 조회한 것처럼 보여주거나 수정·삭제·투표가 성공했다고 표시하지 않습니다.
- 랜덤 대상에서 삭제된 작품은 제외합니다. 선택 직후 삭제되는 경우에는 F08의 예외 처리를 따릅니다.
- 상세 화면의 이전 내용을 어디까지 남길지 같은 표시 방식은 **확인 필요**이며, 남아 있는 작품으로 오해하게 표시해서는 안 됩니다.

### E07. 서버 또는 DB 요청 실패

서버는 화면의 요청을 처리하는 프로그램이고, DB는 작품과 투표를 저장하는 곳입니다. 연결 실패와 저장 실패가 화면에서는 비슷해 보여도 실제 저장 결과가 다를 수 있습니다.

| 상황 | 사용자에게 보일 결과와 확인 방법 |
| --- | --- |
| 목록·필터·상세·순위·랜덤 조회 실패 | 조회 실패 안내를 표시합니다. 정상 조회 결과가 0개인 경우나 작품이 없다고 확인된 경우와 구분합니다. |
| 등록·수정·삭제·투표·취소가 실패했다고 확인됨 | 성공으로 안내하지 않습니다. 테스트에서 저장 전후의 작품·투표를 다시 조회해 실제 결과를 확인합니다. |
| 요청을 보냈지만 서버 응답을 받지 못함 | 결과를 확인하지 못했다는 상황을 성공으로 표시하지 않습니다. 이미 저장되었을 수도 있으므로 '데이터가 반드시 그대로다' 또는 '반드시 저장됐다'고 단정하지 않습니다. |

- 오류 상황을 확인할 때는 연결을 복구한 뒤 실제 작품·투표 상태를 조회해 화면과 비교합니다. 이는 테스트 방법이며, 새로운 자동 복구 기능을 요구하는 것이 아닙니다.
- 등록 실패 시 다시 시도할 수 있어야 합니다. 응답 유실 뒤 등록 요청을 재전송했을 때 중복 작품을 어떻게 처리할지는 **확인 필요**입니다. 기존 문서에 없는 등록 중복 방지 정책을 확정하지 않습니다.
- 자동 재시도, 오류 후 이전 화면 유지 방식, 입력 보존 방식, 정확한 오류 응답은 **확인 필요**입니다.
- 작품과 연결 투표가 모두 제거되어야 한다는 성공 기준은 유지합니다. DB 오류 중 일부만 처리된 경우의 되돌리기 방식은 **확인 필요**이며, 일부만 제거된 상태를 삭제 완료로 판단하지 않습니다.

실패 테스트는 구현 후 별도 테스트 데이터로 진행합니다. 서버 중단, DB 오류 상황, 응답을 받지 못하는 상황을 나누어 확인하며, 이 문서를 작성하는 단계에서 실제 서버나 데이터를 변경하지 않습니다.

### E08. 사진 파일·업로드·저장 오류

F11의 파일 검증, 업로드, DB 저장, 이미지 조회를 나누어 확인합니다. 실패한 등록을 성공으로 표시하지 않습니다. 파일과 DB 중 일부만 저장된 경우와 임시 파일의 정리 방식은 **확인 필요**이며 실제 결과를 재조회해 검증합니다.

### E09. 이미지 방식 충돌

이미지 작품에 사진·AI 두 방식이 함께 전달되거나 출처와 선택 방식이 다르면 거절합니다. 방식 변경 시 기존 입력·결과·진행 중 요청 처리는 정책 확정 후 검증하며 미구현 AI 선택으로 실제 요청을 보내지 않습니다.

### E10. AI 생성 실패·응답 유실·비용 불확실

생성·미리보기·등록 상태를 구분하고 실패를 성공으로 처리하지 않습니다. 응답이 없어도 비용이 발생하지 않았다고 단정하지 않습니다. 재시도·취소·중복 요청의 비용 및 정리 기준은 **확인 필요**입니다.

### E11. 이미지 없음과 이미지 로드 실패

기존 텍스트에 이미지가 없는 것은 오류가 아닙니다. 이미지 작품의 조회 실패를 텍스트 전환·작품 삭제·전시관 0개로 처리하지 않습니다. 이미지 대체 안내와 재시도 방식은 **확인 필요**입니다.

## 4. 공통 테스트 준비와 완료 판정

### 준비 방법

1. 서로 다른 ID를 쓰는 브라우저 A, B, C를 준비합니다. ID 형식이나 저장 위치는 미정이므로 특정 도구를 전제하지 않습니다.
2. 테스트용 작품으로 다섯 카테고리, 등록 시각이 다른 작품, 투표 수가 같은 작품을 준비합니다.
3. 작품 0개·1개·10개 미만·11개 이상인 상태는 테스트 데이터를 이용해 구분해서 확인합니다. 순위의 동점 처리용 동일 시각 자료도 테스트 데이터로 준비합니다.
4. 권한 테스트는 A의 작품을 B가 수정·삭제하려는 방식으로 진행합니다. 투표 테스트는 본인 작품 투표 정책과 분리하여 B·C가 A의 작품에 참여합니다.
5. 각 저장 동작 후 새로고침과 다른 브라우저 조회로 실제 유지 상태를 확인합니다.

### 함께 확인할 항목

- ID 저장 정보가 유지되면 재방문해도 본인 작품과 투표 상태가 유지되는지 확인합니다.
- 저장 정보를 지우거나 다른 브라우저로 접근하면 이전 작품을 본인 작품으로 관리할 수 없을 수 있음을 확인하고 안내 문구를 점검합니다.
- 휴대전화와 PC에서 핵심 버튼과 입력칸을 사용할 수 있는지 확인합니다.
- 처리 중 표시, 실패 안내, 빈 결과 안내, 없는 작품 안내가 상황에 맞게 구분되는지 확인합니다.
- 기본 MVP는 F01~F08·F09·F10 작가명 부분, 사진 포함 MVP는 추가로 F10 단일 이미지 방식·F11·F13 텍스트/사진 부분과 E08·E09·E11을 확인합니다. F12·F13 AI 부분과 E10은 확장 단계에서 별도 확인합니다. 미정 정책에 의존하는 테스트는 '확인 필요로 판정 보류'이며 통과로 처리하지 않습니다.
- 이 문서는 테스트 시나리오를 정의합니다. 코드·패키지·DB·서버를 생성하거나 테스트를 실행한 결과는 포함하지 않습니다.

## 6. 이번 버전의 범위 유지

댓글·답글, AI 핑계 문장 생성, 정식 회원가입·로그인, 검색, 알림, 팔로우, 개인별 추천, 별도 관리자 화면은 계속 제외합니다. 사진 업로드·사진전은 사진 포함 MVP에 추가하고 AI 회화전은 핵심 완성 후 확장으로 분리합니다. 복잡한 실제 목록 정렬 옵션과 무한 스크롤은 후순위이며 삭제 작품·방문객 ID 복구는 제공하지 않습니다.

기존 “텍스트만 / 이미지 제외”와 입력 항목은 이번 사용자 요청에 따라 단계적으로 확장했습니다. 다른 확정 정책은 유지하며 미정 값을 임의로 확정하지 않습니다. 사진 저장은 이미지 매체와 작품을 연결하고, AI 생성 결과 확인과 등록은 분리해야 합니다. 필요한 논리 정보는 작가명·유형·출처·미디어 참조·AI 스타일/진행 상태이지만 정확한 API·DB 표와 필드는 **확인 필요**입니다. Phase 1의 샘플 객체를 실제 DB 스키마로 간주하지 않습니다.

현재 실제 백엔드는 `GET /api/health`뿐이고 사진·AI·작품 DB 기능은 없습니다. Phase 0 기록과 현재 Phase 1 코드·디자인은 보존하며, 신규 기능은 계획으로만 반영합니다. 이번 개정으로 PROGRESS의 완료 상태를 바꾸거나 신규 테스트 통과를 주장하지 않습니다.
