브라우저 자동화 도구가 Windows에서 현재 URL을 확인하지 못해 중단되었습니다. 따라서 다음 항목은 성공으로 기록하지 않습니다.

- 전시 관람하기 클릭으로 /gallery 이동, 뒤로가기 및 직접 새로고침.
- 각 카테고리 버튼 클릭으로 카드 변경·선택 표시·전체 복귀.
- 샘플 정렬 선택과 카드 순서 변경.
- 기증·작품 카드·명예의 전당 클릭으로 준비 중 dialog 열기·확인·Escape 닫기.

4. 별도 작품 설명 영역에서 생성 내용을 미리보기·수정합니다. 확인 체크를 선택한 설명만 `refined_description`과 `description_confirmed: true`로 기증 요청에 포함합니다. 확인하지 않으면 설명을 보내지 않고 기존 텍스트 작품으로 기증할 수 있습니다.
5. 원문·제목·카테고리 또는 설명 수정 시 확인 체크를 해제합니다. 생성 당시 원문/카테고리와 달라지면 오래된 추천 안내를 표시합니다. 요청 도중 원문을 수정해도 결과에 당시 입력을 연결해 경고할 수 있도록 했습니다.
6. 새 생성 실패 시 기존 추천·편집 중 설명·작품 입력은 유지합니다. 일반 텍스트 기증을 막지 않습니다. 생성 중에는 중복 요청과 기증 완료를 잠시 막고, 응답 후 사용자 확인을 거칩니다.
7. 상세 화면은 최종 제목과 별도 설명을 보여주고 `원문 핑계 확인하기`를 펼쳐 원문도 확인할 수 있습니다. 설명 없는 기존 작품은 기존 임시 설명으로 표시됩니다.

### 모델·호출·키·비용 제어

- 기본 모델: **`gpt-5.6-terra`**. 확인한 공식 문서에서 지능·비용 균형을 갖춘 기존 mini급 모델로 설명하고, Responses API·Structured Outputs를 지원합니다. 이 짧은 제목·해설 작업에서는 `reasoning.effort: none`을 사용합니다. 최신·최저가 모델이라고 가정하지 않습니다.
- 호출: FastAPI의 `backend/curator.py`에서 Python 표준 HTTP 클라이언트로 고정 주소 `https://api.openai.com/v1/responses`에 POST. `text.format`의 strict JSON Schema로 `titles` 3개와 `description_sentences` 2~4개를 요구한 후 Pydantic으로 다시 검사합니다. 배열의 문장은 최종 설명 한 개로 조합합니다.
- 제목 길이 2~50자·한국어·개수·중복/매우 유사한 후보, 설명 언어·문장 형식·길이를 검증합니다. 원문에 없는 구체적 사실을 만들지 않도록 지시하고 사용자 확인을 요구합니다. 구조 검증이 사실 충실도나 문학적 품질을 보장하는 것은 아닙니다.
- 사용자 버튼에서만 호출, 생성 요청당 OpenAI POST 1회, 자동 재시도 없음. HTTP 리다이렉트도 따르지 않습니다. 출력 상한 1000토큰, `store: false`, 네트워크 timeout 기본 20초(설정 범위 5~25초), 브라우저 대기 상한 30초입니다.
- 단일 서버 프로세스 메모리 기준 10분 동안 방문객별 5회·연결 IP별 10회·프로세스 전체 30회, 동시 처리 최대 2건입니다. 같은 방문객 또는 IP의 동시 요청과 같은 방문객/요청 UUID 재전송은 409, 횟수/전체 동시 한도는 429입니다. 제공사로 보낸 실패 요청도 횟수에 포함합니다.
- 메모리 제한은 재시작 시 초기화되고 여러 worker/서버 사이에서 공유되지 않습니다. 데모 방문객 ID를 인증으로 신뢰하지 않으며 IP별·전체 제한을 함께 둡니다. 공개 서비스의 공유 제한/인증·운영 한도는 이후 별도 작업입니다.
- `OPENAI_API_KEY`, `OPENAI_CURATOR_MODEL`, `OPENAI_CURATOR_TIMEOUT_SECONDS`는 백엔드 프로세스 환경변수만 사용합니다. `backend/.env.example`에는 빈 키와 설정 예시만 있습니다. 예시 파일을 자동 로드하지 않으며 README의 마스킹 입력 예시로 설정할 수 있습니다. 키를 새로 발급하거나 사용자 키를 출력·코드·브라우저·로그·Git에 넣지 않았습니다.
- 키 없음 503, 제공사/연결 오류 503, 시간 초과 504, 거절·중단·잘못된 형식 502를 안전한 문구로 반환합니다. 원본 제공사 오류·키·요청 본문을 반환/로그하지 않습니다. 누락된 키 때문에 서버 시작이나 일반 작품 등록·조회가 실패하지 않습니다.
- 공식 문서 확인: [모델](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [운영·API 키](https://developers.openai.com/api/docs/guides/production-best-practices). 확인일 2026-11-02.

### SQLite와 호환성

- 이미 존재하는 선택 컬럼 `refined_description`을 사용하므로 새 테이블/컬럼이나 DB 초기화가 필요하지 않습니다. 이전 스키마에 컬럼이 없으면 기존 `database.initialize()`의 비파괴 컬럼 추가 경로가 적용됩니다.

### 비용·접근 권한

2026-11-02 공식 문서 기준 GPT Image 2의 1024² 예상 출력은 low $0.006 / medium $0.053 / high $0.211이고 입력 프롬프트 비용은 별도입니다. 최신 GPT Image 2.5 Flare/Sunburst도 검토했으며 출력 $30/100만 토큰, low~max 옵션입니다. GPT Image 1.5는 Deprecated 표시라 선택하지 않았습니다. 현재 지원 API와 크기별 출력 비용을 확인할 수 있는 GPT Image 2를 선택하고 앱은 medium 정사각 한 장으로 고정했습니다. [공식 생성 가이드](https://developers.openai.com/api/docs/guides/image-generation), [API](https://developers.openai.com/api/reference/resources/images/methods/generate).

### DB·파일 보존

- 기존 `artworks`의 선택 메타데이터 필드를 그대로 사용하며 원문·번호·날짜를 보존합니다. 새 `image_generations` 테이블만 추가하고 생성 시도/비공개 준비/해시 토큰/작품 연결/예약액을 기록합니다. 후보 제목이나 원본 PNG 바이트를 작품 테이블에 넣지 않습니다.
- `uploads/paintings/{서버 UUID}.png`는 Git 제외·비공개 디렉터리입니다. 외부 URL 다운로드나 임의 경로/사진 업로드를 받지 않습니다. PNG 컨테이너·치수·청크 체크섬을 확인한 뒤 임시 파일→flush/fsync→원자적 이름 변경→준비 기록 순으로 처리합니다.
- 생성 응답의 미리보기는 브라우저 메모리에만 표시합니다. 무작위 확인 토큰은 DB에 해시로 저장하며 URL·localStorage에 넣지 않습니다. 생성만 하고 떠난 결과는 공개 작품이 아닙니다.
- 기증 시 토큰·방문객·작품 내용·만료·파일 해시를 검사하고 DB 트랜잭션으로 작품/이미지를 함께 연결합니다. 파일 저장·준비 기록 실패는 새 파일을 정리하고, 기증 연결 실패는 작품 삽입을 함께 되돌립니다. 재시도는 같은 기증 요청으로 중복 저장을 막습니다.

- 이번 작업은 실제 DB를 마이그레이션하거나 기존 개발 서버를 재시작하지 않았습니다. 새 테이블은 사용자가 백엔드를 재시작할 때 안전하게 추가됩니다. 테스트는 임시 DB/폴더만 사용했고 실제 DB SHA-256이 작업 전후 동일했습니다.
